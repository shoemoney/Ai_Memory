# Local retrieval methods

> The raw resource, process and cleanup logs mentioned in this document are not published; the summaries and figures derived from them are kept.

Label-based retrieval comparison for the numerical claims in Chapters 05 and 14. This experiment uses public relevance labels, not a generated-answer judge. It uses different corpora and models from the original published evaluations.

Regenerate the evaluation from this directory with `FRESH_RUN=1 bash run.sh`. The fresh mode archives prior per-query outputs and prefixes in scratch and removes derived data/vector checkpoints, while retaining pinned downloads and weights; it refuses to reset an active benchmark. Use `bash run.sh` to resume checkpoints, including the shipped outputs. Requires Linux x86-64, `uv`, Python 3.12, network access, and an 8 GB NVIDIA GPU with sufficient free memory for the chosen batch size. The script downloads data and weights into `/data/scratch/membench/retrieval-methods`, checks GPU compute processes and free memory before loading each model, and checkpoints generated prefixes and per-query rankings. Wave models run one at a time. An explicitly allowed small resident service and graphics processes may coexist; authorized resident PIDs are passed with `ALLOWED_GPU_PIDS` (empty by default). The model job is capped at 5.5 GiB with at least 1 GiB free, and prefix slots are halved when possible after a size-budget or allocation failure. Free-headroom interruptions unload the owned model, wait for the configured preload availability (4.75 GiB in the final compact phase), and resume from checkpoints; one-slot allocation failures halt rather than retry at the same size. Headroom is checked every ten completed prefixes in the final generator. `requirements.lock.txt` pins the tested Python environment; llama.cpp is build b12627, commit 225a5345b. Default model endpoint is localhost:39790. No commercial inference API is used. All baseline and contextual embedding and reranking runs used the 8 GB NVIDIA GPU. Prefix generation began on an Apple M1 Ultra with 64 GB, continued on an Apple M3 Ultra with 96 GB, and resumed on the 8 GB NVIDIA GPU when it had room. Hardware is recorded per phase. Mac request times are operational records and are not compared to GPU timings.

Set `SSH_TARGET` in the environment to an explicitly assigned Apple Silicon model-serving machine to use the pressure-supervised remote prefix server. It checks system-wide free memory before loading, stops only its own model on kernel warning or critical pressure, and exposes only a localhost tunnel. All datasets, indexing, and scoring stay on the development machine; only model serving runs remotely. No global packages are installed.

The default command evaluates BM25, MiniLM dense retrieval, reciprocal rank fusion (k=60), and RRF plus an open MiniLM cross-encoder on all four sets. It additionally generates Qwen3.5-4B Q4_K_M contextual prefixes and evaluates contextual BM25, dense, RRF, and reranked RRF on SciFact, NFCorpus, and LoCoMo. Contextual RRF and contextual reranking make the Anthropic comparison more informative than comparing uncontextualized hybrid retrieval to the published contextual pipeline.

## Data and scoring

- SciFact: all 300 test queries and the complete 5,183-document corpus.
- NFCorpus: all 323 test queries and the complete 3,633-document corpus. Graded relevance is preserved for nDCG.
- LoCoMo: 150 seeded uniform questions with valid author-provided evidence IDs, drawn from 1,533 eligible questions across ten conversations. Exclude category 5, empty evidence, and three questions with unmapped evidence IDs. Map exact turn IDs to their original sessions; candidates are restricted to the question's original conversation. Index all 272 raw dialog sessions, including dates and provided BLIP captions; exclude answers, generated observations, and generated session summaries. No images are fetched. Candidate haystacks contain 19 to 32 sessions, so top-20 recall has a strong ceiling effect; recall@5 and nDCG@10 provide additional resolution. This supplies the complete conversational-memory comparison.
- LongMemEval cleaned standard-s: a fixed uniform sample of 150 answerable questions, seed 20261122, excluding `_abs` questions and questions without answer-session labels. Each question searches only its original standard haystack. The query sample and all corpus/session IDs are reproducible from the pinned dataset revision. Positive qrels are the dataset's `answer_session_ids`; all chunks in an evidence session inherit session relevance for document-level scoring. This is session evidence retrieval, not answer accuracy or precise evidence-turn retrieval.

Data comes from the official BEIR Hugging Face mirrors, the LongMemEval maintainer's dataset repository, and the official LoCoMo repository. `results/manifest.json` records exact dataset revisions, file SHA256 hashes, sampling, counts, and model revisions. `results/sources.json` records primary-source URLs and capture hashes. BEIR dataset cards declare CC BY-SA 4.0; original SciFact annotations separately use CC BY-NC 2.0. LongMemEval's dataset card declares MIT. LoCoMo's official repository declares CC BY-NC 4.0; its data-derived prefix outputs retain the notice in `results/locomo-attribution.txt`. Dataset copies and weights are fetched by script and excluded from deliverables.

Source texts are split into 180-word chunks with 30-word overlap. Keyword tokenization uses Unicode `\w+`, lowercased, with BM25Okapi defaults k1=1.5 and b=0.75. Keyword statistics use the original candidate chunks for each conversational question and the full corpus for BEIR. Conversational candidates are restricted to the original conversation or haystack. MiniLM normalizes 384-dimensional embeddings and uses exact cosine search, with its 256-token input limit. Each leg retains its best chunk for each document/session, then returns its first 150 distinct documents. RRF fuses these document ranks with constant 60 and keeps the best 150 unique documents. A representative chunk from the BM25 leg is used when both legs return the same document; otherwise the dense chunk is used. The cross-encoder reranks that fixed pool with a 512-token pair limit. Ties are deterministic. This chunk representative policy differs from reranking every chunk and is a declared implementation choice.

Context prefixes use the source document followed by the target chunk, without question, answer, qrels, or retrieved candidates. Qwen3.5-4B uses llama.cpp, full model offload except a five-prefix CPU-offload trial, temperature 0, seed 20261122, thinking disabled both by template and reasoning budget, and a 120-token generation cap. Resource-driven changes used one to eight slots and 2,976 to 8,192 tokens per slot. Every fixed prompt, conservative chat-template allowance, and completion fits in the smallest 2,976-token allocation; the maximum requirement is 2,968 tokens. Hardware, batching, context limits, restarts, and resource-driven changes are retained in the raw records. Early Mac rows lack a per-row context-limit field; their deployment history records four 8,192-token slots. The earlier NVIDIA throughput pilot is retained separately and contributes no final prefixes. The final GPU phase uses a 128-token logical prefill batch and 64-token physical batch to reduce working memory; earlier phases used the runtime defaults. The RAM prompt cache is disabled; no checkpoint-state copies accumulate across unrelated documents. The prompt requests 50 to 100 tokens. Source context is capped at 2,500 words; none of the source documents in the three completed prefix arms exceeds that cap. Source-length and output-length counts are reported. The prefix is prepended before keyword indexing, embedding, and contextual reranking. Prefix and chunk compete for the embedding model's 256-token limit, which can reduce access to the chunk body.

Unjudged documents receive relevance zero. Recall@5 and recall@20 use the number of positive qrels as denominator. nDCG@10 follows TREC's linear relevance gains. AP@150 treats any positive relevance as relevant and divides by all positive qrels. Complete miss@20 (the raw `failure20` field) is one if none of the top 20 documents are relevant; it is not one minus recall when multiple documents are relevant. Anthropic defines its published failure metric as one minus recall@20, so the published-versus-local table uses that quantity (`unrecalled20`), including paired relative reductions; the separate complete-miss rate is not its counterpart. Queries are the bootstrap unit, with 10,000 shared resamples, seed 20261122, percentile 95% intervals. Differences and relative failure reductions are paired. If a bootstrap draw has zero baseline failures, the relative-reduction interval is withheld and its undefined-draw count is reported; the absolute paired interval remains available. No interval is pooled across datasets. All-perfect recall also gives a degenerate percentile bootstrap and does not establish perfect population retrieval. An additional Wilson interval is reported for binary miss rates because an all-zero query bootstrap has a degenerate interval and cannot establish a zero population miss rate. These are pointwise, unadjusted intervals. LoCoMo question resampling conditions on its ten supplied conversations and does not estimate uncertainty over new conversations. They cover query sampling, not model, corpus, or implementation uncertainty. The original RRF paper reports MAP; AP@150 here truncates BEIR retrieval but covers each complete memory candidate set (38 to 62 LongMemEval sessions; 19 to 32 LoCoMo sessions). These remain different corpora and fusion inputs from the paper.

NFCorpus has a median of 16 positive documents per query and 144 of 323 queries have more than 20 positives. Its macro recall@20 ceiling is 76.83% even under an oracle ranking, so its 1 minus recall@20 has a 23.17% floor; raw miss percentages should not be compared across corpora. Evidence: `results/data-label-audit.json`.

## Evidence and cleanup

Per-query rankings, scores, generated prefixes, and model token usage are retained in `results/`. The completed run contains 28 method/dataset cells across 923 distinct questions and 18,619 generated prefixes. The independent verifier recalculates scores, checks scope and corpus completeness, checks that reranking only reorders its input pool, and includes a deliberately failing retrieval control. `REPORT.md` is the editor-facing claim inventory. Scratch, local models, and inference processes were removed after scoring; cleanup proof is retained without machine identifiers.
