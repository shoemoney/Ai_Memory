# LongMemEval with local extraction frameworks

> The raw resource, process and cleanup logs mentioned in this document are not published; the summaries and figures derived from them are kept.

Status: finished at **N = 3 paired questions, not the planned 150**. After a long setup and a hardware move, only one history had finished across all four systems when the run was taken over. Measured throughput (about 3 h per history for both frameworks together) allowed three histories in the remaining 8 h, so N was fixed at 3 before further scores were read (decision and arithmetic in `STATE.md`). **Three questions is far too few to rank the systems, and the requested minimum of 150 was not reached.** The first three IDs of the fixed stratified order were completed on all four systems; the run was then stopped.

This experiment measures Mem0 OSS with `infer=True` and Graphiti with entity, relationship, and temporal extraction on full standard LongMemEval_S histories. It reuses the existing BM25 and dense answers, references, and three-vote judgments on exactly the same selected IDs. Graphiti is the permitted alternative to Letta; a native system/tool endpoint probe is a compatibility check, not evidence that every local Letta configuration is impossible.

Run from the repository root:

```bash
MODEL_HOST=user@model-host bash benchmarks/longmemeval-frameworks/run.sh
```

The model-serving machine needs the previously installed MLX-LM 0.32.2 runtime. The client needs `uv`, Python, Docker, SSH, and user systemd. Large client state and HF/UV/PIP caches live under `/data/scratch/membench/longmemeval-frameworks/`; small supervisor control files live under `/var/tmp/membench-longmemeval-frameworks/`. Before large setup writes, the launcher requires at least 20 GiB free on the system disk and records both disk mounts. Cleanup removes both scratch roots. Endpoint configuration defaults to a localhost SSH tunnel on port 39770. `requirements.txt` pins the client environment. The script owns its scratch directory, model-server process, tunnel, and transient service, and removes them at completion or failure. Do not run two copies at once. The absolute deadline persists across retries in `results/authorized-deadline.json`; resuming does not reset the 14-hour budget. For a new experiment, archive the results directory before starting.

## Fixed method

The parent experiment selected 300 of 500 official cleaned LongMemEval_S items. This experiment samples 150 of those 300 with proportional largest-remainder allocation over six non-abstention question types and an abstention stratum, seed 20261122, sorted IDs within strata, then a fixed shuffle. `results/manifest.json` records every ID and allocation. Both frameworks complete question history k before either begins k+1. Only the intersection of completed IDs across all four systems is used for a comparison table. Incomplete histories do not become scored failures or disappear from the planned denominator.

Answer generation and judging use Gemma 2 9B instruction tuned, 4-bit, pinned MLX revision `ff12eb39da2cd9b3b0f4b4f9ffb274603f05bb29`, initially on Apple M1 Ultra, 64 GB, then on an authorized Apple M3 Ultra, 96 GB, after persistent warning-level pressure on the first machine. Every item records its actual hardware class. The one completed M1 framework row is retained; incomplete graph work restarts on M3. Timings are grouped by hardware and never pooled across the two. Framework extraction and memory actions use local Qwen2.5 3B Instruct at 4-bit, revision `4f83f8f146fdf28b512a06562b671d7af4fab457`, whose model card labels the license `other`; the primary model-card evidence is retained in `results/extraction-model-source.json`. It is an open-weight research model, not the answerer or judge. The server drops its previous model and clears the MLX cache before a model switch; at most one model is loaded at a time. The preliminary Gemma-extraction attempts are archived under `results/preflight/gemma-extraction/` and are not included in final framework scores. The client uses CPU embeddings: all-MiniLM-L6-v2, revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`, maximum sequence length 256, normalized vectors. The client GPU is unused.

Reader prompts are identical to the previous experiment, with a 512-token answer allowance and temperature zero. Retrieval returns up to ten memories or facts, with whole lowest-ranked results dropped if needed to fit the native 8,192-token window. The unchanged official task-specific judge prompt receives three temperature-zero calls with seeds 20261122/23/24. The official substring rule interprets `yes` as positive; majority voting is deterministic and does not correct systematic judge errors. An empty answer is forced incorrect before any judge request. The baselines had no empty answers, so this guard does not change their saved labels.

Mem0 0.1.118 uses its actual extraction, memory action, add, and search implementations with local Qdrant and a persistent history database. Only its disabled telemetry event hook is bypassed. Graphiti 0.31.2 uses its actual `add_episode_bulk`, entity and relationship resolution, temporal edges, and hybrid reciprocal-rank search with the Neo4j Community 5.26 backend, pinned container digest `sha256:51d0314ef86074f519003da8dd4daaa9fff72b8479672b742d7cab7f3064e3ed`. The dedicated local database is cleared between histories, so no graph information crosses question histories. The synthetic prerequisite must extract nodes and edges and retrieve a known fact before benchmark ingestion begins. The initial Kuzu backend failed this prerequisite and is excluded from results. Communities are disabled. Graphiti uses the upstream separate node/edge bulk path, four source parts per batch, with upstream previous-episode context and a global limit of four concurrent LLM calls. Graph entity and relationship resolution remain active. Source timestamps include their time of day and are treated as UTC because the source dates have no timezone. A local cosine ranker is supplied so no hosted reranker can be constructed; the default hybrid RRF search does not call it.

Both speakers and source dates are supplied in chronological order. Sessions are split into bounded batches of approximately 2,200 model tokens, with long turns split at 1,800 tokens. All source text is passed through the fixed tokenizer's encode/decode round trip. Each framework attempts every part of the same full history; content/schema errors are recorded by part or bulk batch, any actual SDK writes are preserved, and the harness proceeds without removing that question from the accuracy denominator. This is end-to-end accuracy of the local pipeline including extraction failures, not conditional accuracy on successful ingestion. Transient transport failures are recorded and retried within the absolute deadline; deadline and storage failures stop or pause the run. The benchmark answer and question are excluded from ingestion. Gemma 2 has no system role, and its reader/judge prompts use one user message. Framework extraction preserves Qwen's native system/user roles; the earlier folded-message trial is archived and excluded from primary results. JSON is requested in plain text, fences are removed only when they enclose the entire output, and invalid JSON or schema violations are retained, never replaced with fabricated empty objects. Mem0 extraction and actions have a 1,536-token generation limit; Graphiti has a 4,096-token limit and up to two separately recorded JSON/schema formatting repairs that are instructed to preserve the extracted factual content. Mem0 receives the raw model string so its own SDK retains control of parsing and empty-fact/error handling. The extraction model has a 32,768-token native window; local input budgeting uses its exact pinned Qwen tokenizer, and actual served-model usage is recorded by the server. Answering and judging retain the exact Gemma tokenizer and 8,192-token native window. These are local adapter choices, not vendor defaults.

## Evidence and limits

The dataset is fetched from the official `xiaowu0162/longmemeval-cleaned` repository at revision `98d7416c24c778c2fee6e6f3006e7a073259d48f`, MIT according to its dataset card. The client is a 32-thread x86 CPU with 32 GB of installed memory. Its SHA-256 must match the parent experiment. No dataset or weights are committed. Primary-source URLs and fetched evidence are in `results/sources.json`.

`results/items/` contains question IDs, answers, scores, and provenance. `results/calls/` retains prompt hashes, raw model responses, usage, and duration for actual model requests. Failed graph batches cancel sibling coroutines and drain already-running model requests before the next batch or history begins. `results/ingestion/` checkpoints every attempted history part, source hash, framework events or explicit data error, and elapsed time. A bulk batch's elapsed time is assigned to its first part and zero to its other parts so summing checkpoints counts each batch once. Ingestion error counts are reported alongside accuracy. API token totals cover completed responses; token use from interrupted or failed transport calls can be unknown. Cached model responses can accelerate recovery; this run's wall time and total actual model-request seconds are different quantities and do not validate a vendor latency claim. A failed process can replay an incomplete history after its scratch database has been cleaned; completed scored histories are retained. `results/proof/` and an unpublished raw log retain scrubbed disk/process evidence and checks for preserved preexisting voice processes. Checkpoint completion, not process liveness, is the progress measure.

Published anchors are Mem0's managed 94.4% LongMemEval result, retrieval budget 200, headline N unstated, and Zep's reported improvement of up to 18.5% and roughly 90% lower latency. The local OSS frameworks, different model, native window, adapters, and reduced sample cannot reproduce the managed algorithms or directly validate those headline comparisons. No dollar-cost crossover is measured.

All intervals are descriptive 95% Wilson intervals; stratification, shared histories, and judge errors limit their interpretation. The tester directly reviewed forty randomly selected reused baseline judgments, agreeing with 38/40. This is implementation-agent review, not independent human evaluation, and it does not validate framework-specific judgments. `results/baseline-manual-audit.json` records every decision, including a precision disagreement and the official temporal off-by-one allowance. A separate preselected framework-inclusive audit plan is retained in the manifest. Final figures and editorial replacements will be recorded in `REPORT.md` after the run.

The pressure guard distinguishes loading from reuse. New weights require normal kernel pressure and at least 40% system-wide free memory. At normal pressure, a previously loaded model may continue below 40% only when its owned server PID and last successful model selection are verified. A lease is invalidated before a model switch and on any request failure; PID changes invalidate it as well. If a switch needs memory, only the owned model server is released, and the supervisor resumes it after the load threshold is met. Warning or critical kernel pressure still stops the owned server immediately. Tests cover stale/missing/malformed heartbeats, resident-model continuation, new-load rejection, PID changes, request failures, and no cross-model overlap.

Transport recovery at 11:41 UTC: the 900-second client timeout abandoned still-running generations and queued retries. The owned worker/server were restarted with a 3600-second HTTP timeout under the same absolute deadline; 36 completed Graphiti parts and their graph were preserved, and only four exact unfinished Episodic stubs with no relationships were deleted before retry. Generation settings did not change. An unrelated redundant lease-finalization call after item checkpointing was removed because API calls already finalize their own lease.
