# General-schema memory-writer benchmark, version two

The frozen sample contains 300 source turns: 150 from LoCoMo and 150 from LongMemEval evidence sessions, with 746 source-reviewed atomic reference facts. Nine Q4_K_M model files and an additional decoder-fix arm for Qwen3.5 4B run at temperature zero with seeds 7, 19 and 43. Prompt and schema were frozen before model calls; hashes are in `protocol-lock.json`. Version one is preserved in `../v1/` as the narrow-schema stress test.

Run from this directory, after setting `SSH_TARGET` to the serving host:

```sh
python3 run_all.py
```

The default deadline is 9.5 hours after launch. Override it with `--deadline` and an explicit ISO-8601 UTC timestamp.

Requires Python 3.14.4 standard library, SSH, and the preexisting Apple Silicon llama-server build 12359, commit b1b770d90. No installation occurs. The server uses Metal on an Apple M3 Ultra, 96 GB; all sampling, HTTP clients and scoring orchestration run on the x86 CPU machine. One model is loaded at a time. The runner uses localhost-only remote port 39744 and tunnel port 39745, context 4,096 per slot, batch 512, microbatch 128, two slots and request concurrency two. Other services and benchmark workloads remain running. System-wide free memory must be at least 40% with normal macOS pressure before loading. A five-second monitor stops only the owned server at warn/critical pressure, or below 40% free on the final M3, and resumes after recovery with at least 40% free before loading. No GPU inference runs on the scoring host.

The writer returns an array of `{fact, subject, category, date}` objects, with at most 12 objects. The eight fixed categories and exact instructions are in `writer_schema.json` and `writer_prompt.txt`. Output cap 1,024, thinking disabled at template and request, server reasoning budget zero, prompt cache false, repetition penalty 1.0 except the separately labeled 4B 1.1 arm. The source turn and speaker are the only writer inputs. Hidden QA answers, earlier sessions, observation annotations and references are excluded.

Sampling seed 20261122 selects 15 LoCoMo turns per conversation: five with preference markers, five with temporal or plan markers, and five other turns. Eligible text is 80–400 characters, contains personal pronouns, has a single-turn-cited observation, and contains no image. LongMemEval contributes 30 questions from each of five types (single-session user, single-session preference, temporal reasoning, knowledge update and multi-session), choosing one eligible answer-bearing user evidence turn per question with the same length and pronoun filters. Assistant-only and abstention questions are excluded. Two duplicate texts were replaced deterministically within their original strata. These filters favor short, personal, annotation-bearing evidence; this is not a representative sample of all conversational traffic. Exact regular expressions and sampling order are in `prepare.py`, and counts and replacements are in `data/manifest.json`.

The source manifests pin official dataset revisions and licences. LoCoMo is CC-BY-NC-4.0; LongMemEval's pinned dataset card declares MIT. The derived LoCoMo portion remains noncommercial under its source licence; this benchmark code does not relicense source material. `python3 prepare.py` rebuilds the sample from pinned downloads and the shipped manual references, attaching the existing audit decisions by source ID. Original corpora stay in the temporary lab. `python3 compile_references.py --check` verifies the reference compilation without rewriting frozen data. `annotations.py` contains manual source-only references by the implementing agent. These are not independently human-adjudicated gold. `data/generated-reference-audit.json` records the random audit of 60 original model-generated observations: 17 contain material detail unsupported by the individually cited turn, 28.3% with nominal Wilson 95% interval 18.5–40.8%. This source-only audit does not establish whether an unsupported detail is true elsewhere in the conversation. The final references were written afresh from source text rather than copied from those observations. [LongMemEval’s primary paper](https://arxiv.org/html/2410.10813v2) describes human-curated questions and evidence locations and human-edited simulated sessions. Its QA answers are not reused as extraction gold; the generated-annotation audit targets LoCoMo’s model-written observations.

Local Qwen3.5 9B Q4_K_M judges source support and explicit contradiction. Reference coverage is a separate premise-only call that receives written facts and reference hypotheses, never the source. Missing information is not contradiction. Extra supported details count toward precision; missing reference facts reduce recall. Fact, subject and date are evaluated together; category correctness is not independently graded beyond schema membership. Source support does not measure long-term memory usefulness. Pseudonymization also replaces some capitalized terms and can affect model behavior. Invalid or truncated outputs write zero accepted facts and receive zero recall. Facts per turn count accepted fact objects; atomicity is requested in the prompt but not independently scored. Precision requires every material detail of an object to be supported, so bundling can affect object counts and precision. The judge's 60 fixed, manually checked calibration pairs and every raw reply are retained. Review labels were authored by the implementing agent, not an independent human.

Each raw writer response is flushed and fsynced per item, along with its request, model, seed, protocol hash, data hash, timing and parse result. Transport failures are recorded separately and retried; model-quality failures are not retried. Three seeds are repeated measurements, not independent examples. The analysis uses 2,000 stratified cluster bootstrap replicates, resampling LoCoMo conversation clusters and LongMemEval question clusters while keeping all seeds together. Degenerate boundary intervals cannot estimate unseen errors. Intervals reflect source-sample variation conditional on the references and judge decisions; they do not include annotation or judge error. Model-arm order is independently randomized for each seed. Endpoint latency includes completed HTTP responses and generation with two concurrent requests, including model-quality failures; it excludes failed transport attempts, recovery waits, loading and download. Interrupted transport attempts are logged separately. Shared-host timings do not establish production throughput, and latency intervals do not model changes in host load. Training-data exposure to these public datasets was not audited.

The M1 pilot is preserved in `results/m1-pilot/`; the former M3 pilot is in `results/m3a-pilot/`. After repeated M1 warning-pressure reloads, the run moved to a shared M3. It then moved again when that instance crossed a sibling deadline-bound run's 40% free-memory threshold. All 9,000 main requests restart on the final M3 instance, identified as `M3 main` per request. Main quality and timing use that instance exclusively. The 50 paired controls for Qwen3.5 4B repeat-1.1 at seed 7 are in `results/hardware-overlap.jsonl`; earlier controls are retained separately. `results/migration.json` and `results/relocation.json` record removal of scratch on both earlier serving instances. The original M1 voice listener PIDs were unchanged.

`results/diagnostic/` reproduces the original 4B failure on the M1 under the original v1 prompt, schema, 512-token cap and single slot. The default produced 79/100 complete outputs. Doubling the cap rescued 0/21 failures. Changing only `repeat_penalty` to 1.1 produced 100/100 complete outputs. All calls reported zero reasoning characters; template rendering confirms the thinking-off prefix closes the think block. The observed failure is repetitive continuation inside unconstrained-length string fields until the output cap, not hidden reasoning consuming that cap. This diagnosis establishes a decoder-sensitive failure for these files and prompts, not a universal 4B defect.

Results, clustered intervals, limits and final cleanup evidence are added to the root README and REPORT after completion. Model paths and downloads stay in the ownership-checked remote temporary directory and are deleted at successful completion or deadline. Existing output checkpoints are resumed; move result files aside for a fresh run.

The coverage matcher supplies only the input speaker identifier binding alongside written claims. It never receives the original conversation text. This serialization adjustment was frozen after manual review and before actual semantic scoring; the same 60 randomly selected actual pairs were retained. See `matching-protocol.json` and `data/actual-output-audit.json`. Manual labels are implementing-agent judgments, with ambiguous cases noted, and are not independent human adjudication.

The actual-pair audit was blinded to judge decisions, but informed the speaker-binding adjustment. Its agreement therefore is not an untouched held-out validation estimate. The fixed constructed calibration and the actual random audit are reported separately.

The coder pair shares the same backbone dimensions. Its serialized element-count difference equals a separate output head, not a larger backbone; 33 shared tensors also differ in quantization type. `inspect_coder_headers.py` downloads only pinned GGUF header ranges and records this evidence. This comparison cannot isolate abliteration.
