SQLite and other stores

One database holds text, keyword index and vectors rebuilt from JSONL; the survey compares other stores.

Maturity

What it is

A laptop assistant stores notes, a keyword index and per-note vectors in one database file. SQLite provides FTS5 keyword search; sqlite-vec adds the vec0 vector table. Both run through one in-process connection, without a server.1,2 Pick it when one user or host owns the memory.

The JSONL log is the source of truth; searches read a rebuilt SQLite index. The survey compares neighboring stores. Memory kinds (semantic, episodic, procedural) follow CoALA.3

Terms used in this chapter

JSONL
One JSON object per line; here, the append-only event log.
Materializer
Rebuilds the database from the log; materialize() builds a fresh file or in-memory index.
Supersede
A correction naming the event IDs it replaces as parents.
Tombstone
A log entry recording a deletion.
WAL
Write-ahead logging: a journal mode that lets readers continue during a write.

How it works

Write. An add transaction atomically writes a memories row, FTS5 entry and vec0 vector under one row ID, preserving crash consistency.

Read. Non-empty text merges two searches. Skip embedding and recall for blank queries: they return nothing. This fixture has no vector-only mode. FTS5 returns keyword matches ordered by BM25 (a keyword relevance score).1 vec0 returns nearest vectors (k-nearest-neighbor search, KNN; exact here) through embedding MATCH ? AND k = ?, by L2 distance (straight-line Euclidean distance; smaller is nearer). For cosine ranking, unit-normalize stored and query vectors; record preprocessing (Chapter 03).2 Reciprocal rank fusion (RRF) adds 1 / (60 + rank) per list containing an item; rank 1 is best (60 is usual; see Chapter 05 for BM25 and RRF).

Log underneath. Events contain IDs, keys, operations and parent IDs; materialization rebuilds live state.

Worked example from the test. laptop:1 puts the preference "metric". laptop:2 supersedes it with "imperial", the sole live value. laptop:3 deletes the key permanently; retrying laptop:1 cannot revive it. Replay is arrival-order independent, using an explicit stack for deep histories:

EventWhat it doesRules
putCreates the first value for a key.Takes no parents.
supersedeReplaces earlier values, each named as a parent.Parents must be puts or supersedes of the same key. A supersede missing a parent waits, out of the live index.
deleteRemoves the key.Permanent: recreating the item needs a new key. Takes no parents.

Puts are ready immediately; supersedes wait until every parent is present and ready. Ready values stay live until superseded. Multiple live values are contested; rebuilds exclude them.

Log and SQLite commits are separate: acknowledged corrections and deletes leave stale search results. Block freshness-sensitive reads until a published rebuild includes the acknowledged event (Chapter 17). Without log keys or source event IDs, this fixture cannot validate search candidates against live state.

  • Conflict: supersede changes; give episodes distinct keys. To resolve contention, the app or user appends a supersede naming every live event for that key, then materializes again; only the agreed value enters search.
  • Erasure: a delete is logical; old log bytes keep the text. Protect live logs and databases with file permissions and OS full-disk encryption. Physical erasure needs retention and compaction policies covering archives, backups and derived database files and journals (Chapter 17).

Good for and not for

Good for

  • Personal disk memory for one agent or desktop app.
  • Keyword and vector search merged in application code.
  • A JSONL event log written before any other store.
  • Serialized writes owned by one host.
  • Exact scans within the query latency budget.

Not for

  • Several hosts writing one memory: use PostgreSQL (Chapter 08).
  • Network filesystems: WAL shares memory, requiring all connections on one host; network filesystems were not tested.11
  • Exact scans exceeding the query latency budget: benchmark an approximate index (Chapter 11).
  • The browser as the only copy of user memory.

Numbers

No generative model needed. Probes: benchmarks/stores in the companion repository.

  • Exact search over 10,000 vectors per user evaluates 10,000 L2 distances (3.84 million float components): 15.36 MB of 384-dimension float32 vectors. The 100-user reference layout holds 1.536 GB (about 1.43 GiB); scanning all 100 users evaluates one million distances (384 million components) per query; a per-user file scans only 10,000 vectors (Chapter 00).
  • Shared CPU host, hardware unrecorded: the stores probe (SQLite 3.46.1; sqlite-vec 0.1.9, k = 10) timed 200 serial vec0 queries over 100,000 384-dimension vectors: median 138.6 ms, 95th percentile 154.4 ms. This older SQLite differs from the walkthrough pin; treat timing as order-of-magnitude only. It covers vector SQL and row fetch, not hybrid recall.
  • SQLite permits one writer. With two connections, the second used a 50 ms timeout (the walkthrough uses 5000 ms). It read the committed snapshot during the first’s uncommitted write; its write waited about 50 ms, then failed with "database is locked". This tests contention, not throughput.11
  • In one CPU-only build with a 32 MiB buffer limit, building DuckDB's graph-based vector index (HNSW, hierarchical navigable small world) over 100,000 384-dimension vectors grew process memory from about 138 MiB to 210 MiB: the limit did not cap the RAM-resident index. These measure whole-process memory.

Count embedding and prompt tokens with their respective models’ tokenizers (Chapter 03). Measure log replay, query embedding and KNN search separately. If replay dominates, checkpoint derived state and replay the tail; if KNN dominates, benchmark an indexed alternative (Chapter 11).

Setup walkthrough

Require loaded SQLite 3.51.3 or later, or backports 3.44.6/3.50.7; verify FTS5 and sqlite-vec load. Linux requires CPython 3.14, venv, curl, unzip and a C compiler. Start a separate bash shell: it uses set -e and exports LD_LIBRARY_PATH. Save named listings in lab/. Post-cutoff validation on 23 November 2026 supplements the 22 November research cutoff: CPU only, a 32-thread consumer CPU, Python 3.14.4, SQLite 3.51.3 (locally compiled) and sqlite-vec 0.1.9. Text and four-dimensional synthetic vectors test correctness, not retrieval quality, without models or datasets.

One trusted process owns the log. Never overlap events() with append or rotation: reads can repair tails and need write permission. Use a local filesystem honoring fsync. File sync makes bytes durable; parent-directory sync makes the new filename durable before truncating the old log. Choose JSONL for grep, DuckDB scans and device export despite broken SQLite schemas or extensions. Without that need, a separate SQLite events database replaces fsync, tail repair and rotation code with journaling.

  2. Write the memory module

    WAL allows reads during writes; busy_timeout makes another writer wait up to 5000 ms. The FTS5 table uses content='memories', indexing that table without copying text.1 quote() wraps every word in double quotes so FTS5 treats each as a literal and joins them with OR: one matching word recalls a row and BM25 ranks it (a space join would require every word). hybrid() runs both searches and the row lookups in one read transaction and fuses the lists with RRF; remove_indexed_row() removes indexed rows. User deletion appends a tombstone, then rebuilds; log keys lack row-ID mappings. A collection is one database file per embedding identity. Call add only outside an existing transaction: it can commit or roll back caller work. Initialization errors before identity checks or during schema creation can leak connections; harden connect before production.

    For substrings, replace the FTS5 declaration with fts5(content, content='memories', content_rowid='id', tokenize='trigram'); substrings under three characters match nothing. For existing databases, recreate this table, rebuild from memories and rerun the recall check.

    import json, math, sqlite3, struct
import sqlite_vec

DIM = 4  # use your embedding model's size, for example 384

SPACE = dict(model="toy-4d", revision="fixture-v1", dimensions=DIM,
             preprocessing="identity")

def identity(space):
    if set(space) != {"model", "revision", "dimensions", "preprocessing"}:
        raise ValueError("invalid embedding identity")
    if type(space["dimensions"]) is not int or space["dimensions"] != DIM:
        raise ValueError("invalid embedding dimensions")
    if any(type(space[k]) is not str or not space[k].strip()
           for k in ("model", "revision", "preprocessing")):
        raise ValueError("invalid embedding identity")
    return json.dumps(space, sort_keys=True)

def check(db, space, vector=None):
    saved = db.execute("SELECT identity FROM collection WHERE id=1").fetchone()
    if saved != (identity(space),):
        raise ValueError("embedding space mismatch")
    if vector is not None:
        if len(vector) != DIM or not all(math.isfinite(x) for x in vector):
            raise ValueError("invalid embedding vector")

def connect(path, space):
    wanted = identity(space)
    db = sqlite3.connect(path)
    db.execute("PRAGMA journal_mode=WAL")
    db.execute("PRAGMA busy_timeout=5000")
    db.enable_load_extension(True)
    sqlite_vec.load(db)
    db.enable_load_extension(False)
    try:
        with db:
            db.execute("CREATE TABLE IF NOT EXISTS collection "
                       "(id INTEGER PRIMARY KEY CHECK(id=1), identity TEXT)")
            saved = db.execute("SELECT identity FROM collection").fetchone()
            if saved is None:
                if db.execute("SELECT 1 FROM sqlite_master "
                              "WHERE name='memories'").fetchone():
                    raise ValueError("collection identity missing; rebuild")
                db.execute("INSERT INTO collection VALUES (1, ?)", (wanted,))
            check(db, space)
    except Exception:
        db.close()
        raise
    db.executescript(f"""
    CREATE TABLE IF NOT EXISTS memories(id INTEGER PRIMARY KEY, kind TEXT,
      content TEXT, embed_model TEXT,
      created_at TEXT DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')));
    CREATE VIRTUAL TABLE IF NOT EXISTS memories_fts USING fts5(
      content, content='memories', content_rowid='id');
    CREATE VIRTUAL TABLE IF NOT EXISTS memories_vec USING vec0(
      embedding float[{DIM}]);
    """)
    return db

def vec(v):
    return struct.pack(f"<{len(v)}f", *v)

def add(db, kind, content, vector, space):
    with db:
        check(db, space, vector)
        cur = db.execute(
            "INSERT INTO memories(kind, content, embed_model) VALUES (?,?,?)",
            (kind, content, space["model"]))
        rid = cur.lastrowid
        db.execute("INSERT INTO memories_fts(rowid, content) VALUES (?,?)",
                   (rid, content))
        db.execute("INSERT INTO memories_vec(rowid, embedding) VALUES (?,?)",
                   (rid, vec(vector)))

def quote(text):
    return " OR ".join('"' + w.replace('"', '""') + '"' for w in text.split())

def hybrid(db, text, vector, space, k=3, pool=20, rrf_k=60):
    own = not db.in_transaction
    if own:
        db.execute("BEGIN")  # one snapshot for both rankings and the lookups
    try:
        check(db, space, vector)
        if not text.strip():
            return []  # no search at all, including no dense branch
        fts = db.execute(
            "SELECT rowid FROM memories_fts WHERE memories_fts MATCH ? "
            "ORDER BY rank LIMIT ?", (quote(text), pool)).fetchall()
        knn = db.execute(
            "SELECT rowid FROM memories_vec WHERE embedding MATCH ? AND k = ? "
            "ORDER BY distance", (vec(vector), pool)).fetchall()
        score = {}
        for ranked in (fts, knn):
            for i, (rid,) in enumerate(ranked):
                score[rid] = score.get(rid, 0) + 1 / (rrf_k + i + 1)
        top = sorted(score, key=score.get, reverse=True)[:k]
        return [(r, round(score[r], 4)) + db.execute(
            "SELECT kind, content FROM memories WHERE id = ?", (r,)).fetchone()
            for r in top]
    finally:
        if own:
            db.rollback()

def remove_indexed_row(db, rid):
    if db.in_transaction:
        raise ValueError("removal requires its own write transaction")
    db.execute("BEGIN IMMEDIATE")  # lock before reading the old FTS text
    try:
        row = db.execute("SELECT content FROM memories WHERE id = ?",
                         (rid,)).fetchone()
        if row:
            db.execute("INSERT INTO memories_fts(memories_fts, rowid, content) "
                       "VALUES('delete', ?, ?)", (rid, row[0]))
            db.execute("DELETE FROM memories_vec WHERE rowid = ?", (rid,))
            db.execute("DELETE FROM memories WHERE id = ?", (rid,))
        db.commit()
    except BaseException:
        db.rollback()
        raise

  4. Make the log the source of truth

    Newlines complete records. Acknowledge appends after file and directory syncs succeed; retry lost acknowledgements with identical IDs and payloads. Recovery truncates unfinished final records; malformed records and conflicting IDs raise errors. Generate IDs once (production UUIDs; demo device:counter). episodic_log.py accepts any memory kind; the fixture discards kind and indexes everything as semantic. Preserve kind if filtering by it.

    Log.append() replays all part files per append; rotation cannot bound write cost. Writers can cache events and rescan on startup. Rotation fsyncs a copy, publishes it atomically, syncs the directory, then truncates the active file. Interrupted rotation leaves duplicates; replay deduplicates by event ID.14

    pythonepisodic_log.pyTested
    import json, os, shutil
from pathlib import Path

class Log:
    # One writer; stop readers/sync while recovering or rotating.
    def __init__(self, folder):
        self.root = Path(folder)
        self.root.mkdir(exist_ok=True)
        self.current = self.root / "current.jsonl"
        self.syncdir(self.root.parent)

    def syncdir(self, path=None):
        fd = os.open(path or self.root, os.O_RDONLY | os.O_DIRECTORY)
        try:
            os.fsync(fd)
        finally:
            os.close(fd)

    def events(self):
        seen = {}
        paths = sorted(self.root.glob("part-*.jsonl")) + [self.current]
        for path in paths:
            if not path.exists():
                continue
            with path.open("r+b" if path == self.current else "rb") as f:
                line_no = 0
                while True:
                    start = f.tell()
                    raw = f.readline()
                    if not raw:
                        break
                    line_no += 1
                    if path == self.current and not raw.endswith(b"\n"):
                        f.truncate(start)  # only an uncommitted final record
                        f.flush()
                        os.fsync(f.fileno())
                        break
                    try:
                        if not raw.endswith(b"\n"):
                            raise ValueError("unterminated archived record")
                        e = json.loads(raw)
                        validate(e)
                        if e["id"] in seen and seen[e["id"]] != e:
                            raise ValueError("event id reused with different data")
                    except (ValueError, TypeError, KeyError) as exc:
                        raise ValueError(f"{path}:{line_no}: {exc}") from exc
                    seen[e["id"]] = e
        events = list(seen.values())
        state(events)  # reject invalid dependencies during replay too
        return events

    def append(self, e):
        validate(e)
        old = {v["id"]: v for v in self.events()}  # recover before append
        if e["id"] in old:
            if old[e["id"]] != e:
                raise ValueError("event id reused with different data")
            if self.current.exists():
                with self.current.open("rb") as f:
                    os.fsync(f.fileno())
            self.syncdir()  # retry must finish any failed durability barrier
            return  # retry after lost acknowledgement
        state([*old.values(), e])  # validate before writing any bytes
        raw = (json.dumps(e, sort_keys=True, allow_nan=False) + "\n").encode()
        with self.current.open("ab") as f:
            f.write(raw)
            f.flush()
            os.fsync(f.fileno())
        self.syncdir()  # also makes first creation durable

    def rotate(self):
        self.events()  # validate all history; repair only active tail
        if not self.current.exists() or not self.current.stat().st_size:
            return
        parts = sorted(self.root.glob("part-*.jsonl"))
        n = int(parts[-1].stem.split("-")[1]) + 1 if parts else 1
        target = self.root / f"part-{n:08d}.jsonl"
        temp = self.root / "rotation.tmp"
        with self.current.open("rb") as src, temp.open("wb") as dst:
            shutil.copyfileobj(src, dst)
            dst.flush()
            os.fsync(dst.fileno())
        os.replace(temp, target)  # same filesystem, atomic publication
        self.syncdir()  # archive durable before touching current
        with self.current.open("wb") as f:
            f.flush()
            os.fsync(f.fileno())
        # Crash before truncation leaves duplicates, removed by event id.

def validate(e):
    fields = ("id", "key", "device", "clock", "op", "text")
    if not isinstance(e, dict) or any(type(e.get(k)) is not str for k in fields):
        raise ValueError("event string fields required")
    if not all(e[k] for k in ("id", "key", "device", "clock")):
        raise ValueError("empty identity or provenance")
    if e["op"] not in ("put", "supersede", "delete"):
        raise ValueError("unknown operation")
    if type(e.get("parents")) is not list:
        raise ValueError("parents must be a list")
    if any(type(p) is not str or not p or p == e["id"] for p in e["parents"]):
        raise ValueError("invalid parent")
    if e["op"] == "supersede" and not e["parents"]:
        raise ValueError("supersede needs parents")
    if e["op"] != "supersede" and e["parents"]:
        raise ValueError("only supersede accepts parents")

def state(events):
    by_id = {}
    for e in events:
        validate(e)
        if e["id"] in by_id and by_id[e["id"]] != e:
            raise ValueError("event id reused with different data")
        by_id[e["id"]] = e
    visiting, ready = set(), {}

    for root in by_id:
        stack = [(root, False)]
        while stack:
            eid, done = stack.pop()
            if eid in ready:
                continue
            e = by_id[eid]
            if done:
                visiting.remove(eid)
                ready[eid] = all(ready.get(pid, False) for pid in e["parents"])
                continue
            if eid in visiting:
                raise ValueError("dependency cycle")
            visiting.add(eid)
            stack.append((eid, True))
            for pid in reversed(e["parents"]):
                if pid not in by_id:
                    continue  # pending, but validate every available edge
                parent = by_id[pid]
                if parent["key"] != e["key"]:
                    raise ValueError("parent key mismatch")
                if parent["op"] not in ("put", "supersede"):
                    raise ValueError("parent must be put or supersede")
                stack.append((pid, False))
    active = [e for eid, e in by_id.items() if ready[eid]]
    dead = {e["key"] for e in active if e["op"] == "delete"}
    replaced = {p for e in active for p in e["parents"]}
    live = {}
    for e in active:
        if e["key"] not in dead and e["id"] not in replaced:
            live.setdefault(e["key"], []).append(e)
    return {k: sorted(v, key=lambda e: e["id"]) for k, v in live.items()}

Restore checkpoints, closes and syncs a fresh disk database, then publishes and reopens it. Switch stopped consumers to a never-used basename without old journals or sidecars. Only first publication is tested. Toy callback tests visibility, not quality.

    Supply a production embedding callback, cached by content hash plus embedding identity. On each write, append, rebuild a fresh file and switch stopped consumers. Sync rules (not tested)

Network sync, browser persistence and browser vector search were not tested. The rules below make retries harmless and track ordered ingestion:

  • Accept: authenticate devices and authorize keys. In one transaction, insert under a unique event ID and assign a server sequence; commit durably, then acknowledge that sequence. An identical retry returns the original sequence; changed payloads are rejected.
  • Pull: devices save pulled events locally before advancing their saved last-seen server sequence number.
  • Conflicts: the server applies the same parent checks, so contested facts stay contested.
  • Tombstones: retain through exports, imports, restores and backups for the longest supported offline-device and backup period, preventing deleted facts from re-entering context; older devices require full resync (Chapter 17).

Browser storage (not tested)

For browser SQLite, start from wa-sqlite's demo/hello at revision 205eed5, which registers IDBBatchAtomicVFS, a virtual filesystem storing database pages in IndexedDB.7,15 The default demo is in-memory; AccessHandlePoolVFS allows one wa-sqlite instance and cannot directly import or export OPFS (origin-private filesystem) files.7,16 Require these checks in every supported browser:

  • Reload: commit, reload and query a memory. Restored editor SQL proves nothing: it uses separate storage. The reset parameter clears storage.
  • Export and restore: export events, including supersedes and tombstones, outside browser storage; restore a fresh database and verify deletions survive.
  • Vectors: for browser vector recall, load your vector implementation, reopen a persisted fixture offline and get the expected nearest row.
  • Multi-tab: allow one writer, or use a backend with coordinated connections; desktop WAL behavior does not carry over.
  • Storage loss: handle refused writes and eviction; browser storage is best-effort by default and users can delete even persistent storage.17

Gotchas

Gotcha: upgrade the SQLite library used by your app

SQLite documents a rare WAL-reset race that can corrupt a WAL-mode database when threads or processes write or checkpoint at once, likely present in SQLite 3.7.0 through 3.51.2; use 3.51.3 or later, or the backports 3.44.6 or 3.50.7. This book did not reproduce the race or validate the fix.11,13

Gotcha: FTS5 reads user text as a query language

MATCH has its own grammar. Local parameterized tests of OR syntax, quoted literals and unfinished quotes returned different results or parse errors. Binding stops SQL injection, not query interpretation. quote() wraps words, doubles internal quotes and joins them with OR (see Chapter 05).1

Gotcha: sqlite-vec is pre-v1, and deletes do not cascade

The README warns of pre-1.0 breaking changes.2 Keep vectors rebuildable. Locally, deleting a memories row left its row ID in both indexes. The step 2 remove_indexed_row() helper locks with BEGIN IMMEDIATE before reading old text, issues the FTS5 'delete' command with it,1 then removes the vec0 and memories rows. All removals commit together. Existing transactions are rejected without ending them; competing removals are tested.

Gotcha: silent embedding drift across model updates

Each database file stores one embedding identity (model, revision, dimensions, preprocessing), checked on every write and query. Mismatches refuse reopen, writes and queries, even for same-length vectors; rebuild into a fresh file (Chapter 03).

Verdict

Verdict: one file first, log underneath

Pick SQLite with FTS5 and sqlite-vec for one agent or desktop app needing local keyword and vector search. Durably record puts, corrections and deletes; rebuild uncontested live state; preserve event IDs and tombstones through sync and restore.

Use PostgreSQL (Chapter 08) for several writing hosts; benchmark a vector store (Chapter 11) on target hardware when exact scans exceed the latency budget. Use MariaDB vectors when tenant data already lives on that server, DuckDB for batch analysis, files for procedures, and checkpoints only for run state. Chapter 21 runs a painter's business on one SQLite file.
