What it is

This chapter calls models changed to refuse less “edited”. Abliteration (defined below) and fine-tuning are two methods. This test evaluates an upload labelled abliterated by its quantizer, not the editing procedure. Fine-tuned builds need their own provenance checks and acceptance tests; they are not evaluated here. An edited memory extractor records turn facts; consider it when stock declines or softens needed medication, debt or divorce facts. “Uncensored” describes intent, not accuracy.

The walkthrough tests two small quantized models on ordinary facts, health, debt, divorce and quoted profanity for a private adult assistant. Stock preserved all 13 acceptance facts; edited reversed two. Both corrupted adult-content probes without declining.

Terms new in this chapter

Abliteration
Abliteration finds a direction (a vector in the model's internal activations) that separates prompts it refuses from prompts it answers, then edits the weights so they can no longer write along it, without further training.12
KL divergence
An asymmetric measure of how far one probability distribution diverges from a reference. Heretic, an open-source tool that automates abliteration, uses it to check how far an edit moves outputs on harmless prompts, not memory accuracy.3

How it works

The extractor proposes facts; the application checks and stores them for later retrieval by the chat model. Swapping Chapter 06's extractor leaves storage unchanged.

What an edit changes

Arditi and colleagues reduced refusals by removing one such direction in the models they studied.12

Heretic seeks fewer refusals while keeping next-token probabilities on harmless prompts close to the unedited model. This checks unrelated output changes, not whether a dose or date survives extraction. Its AGPL-3.0 license does not replace the weights' licenses.3

Good for and not for

Good for

  • A private assistant whose stock extractor refuses facts it should record.
  • Short extraction tasks with explicit expected facts.
  • A local deployment with pinned weights, hashes and runtime settings.
  • Comparisons that include harmless facts, corrections and messages with no extractable facts.

Not for

  • Fixing retrieval errors (diagnose the read path with Chapter 05).
  • Assuming reduced refusal means better accuracy.
  • Replacing permission checks or access controls with model behavior.
  • Choosing edited weights when the stock model passes your tests.

Numbers

Edited recorded Austin as current and Oslo as past; stock preserved every fact. That correction error reversed two propositions. No explicit declines occurred; refusal recovery is unmeasured. Ten mild cases, one prompt and one seed provide anecdotal first-party results, not evidence for other prompts or seeds. Adult-content probes are separate.

Each model saw ten messages once without history: nine contain 13 propositions, including past/current residences; the tenth expects an empty facts array. A proposition combines subject, predicate, value, polarity (true asserted, false denied) and validity (current/past time status, distinct from JSON validity). Scoring:

  • Refusal: an explicit decline counts as an observed refusal.
  • Omission: a missing expected fact. An unexpected empty array counts as omissions without distinguishing a decline, missed facts or finding nothing.
  • Addition: an unsupported fact. Other wrong values, including softening (“takes medication” for “fluoxetine 20 mg”), count as an omission plus an addition. Tag softened expected propositions separately during review.
  • Reversal: flipped polarity or swapped current/past on an otherwise identical fact, counted once. A changed value instead counts as an omission plus an addition.
  • Syntax and schema failures (duplicates and extra fields included) count per response; semantic counts cover schema-valid responses only.

The schema allows owes, excluding owed; this run cannot test unaided wording. Both models ignored the subject instruction; the script maps I/me to user. Different sizes, llama.cpp releases and parameter counts prevent isolating abliteration. Ollama reports the counts above despite edited's 1.5B card name; abliteration cannot add parameters. The extra 233,373,696 equal 151,936 × 1,536 (vocabulary by hidden size), an output matrix mapping the final hidden state to vocabulary scores. Header inspection found no separate output.weight in stock; edited has one with these dimensions. Stock may share (“tie”) output and input embeddings. Treat them as different builds.

The official collection has no small models,8 so uploads named Qwen3.8 2B, 4B or 9B are community builds before any edit, as are the unedited empero-ai 2B, 4B and 9B distills Chapter 06 tested for extraction.9

Chapter 06 is the closest prior evidence, and the reason a human scores refusals here. On 100 refusal prompts against the petruhonk 9B Heretic build, the card reported 6 refusals, a keyword rule counted 14 and a human reader counted 43, so the card and the keyword count both understated them.10 The unedited model it was edited from refused 98 of 100 in the same rerun.

Scope and scale

Each saved turn costs one model call (twenty here). Reads cost none; retrieved notes consume answering-model input tokens. The fixture caps context at 2,048 tokens and output at 512. Normal calls unload afterward. memtest.py warm stock preloads, times a second plain-case call with keep_alive, then unloads; that call took 5.416 s. Reading and parsing the two-fact note took 0.064 ms with a warm file cache. Both timings are anecdotal.

Share weights across users: about 2.1 GB for both files, plus Ollama copies and runtime memory. At 1 KB per accepted note, 100 users × 1,000 notes need about 100 MB before indexes and logs (sizing reference, Chapter 00). For slow writes, see Chapter 06; for slow scans, add Chapter 05 retrieval and Chapter 08 storage.

  5. Save the complete acceptance test

    The schema forces a facts object; refusals may appear as empty arrays. Read each response for explicit declines. memtest.py records responses and scores full propositions under the Numbers rules. The API request sets num_gpu: 0. To audit your deployment, replace the cases and predicate list (fitted to this fixture) with messages from your traffic, including cases where your stock extractor refused or softened a fact (none is demonstrated here). Use only synthetic or permission-cleared, de-identified fixtures: responses.jsonl, reviewed.jsonl, reviewed.json, free.jsonl and memory.json retain extracted values.

def ask(model, text, constrained=True, keep_alive=0):
    body = {'model': model, 'stream': False,
            'keep_alive': keep_alive, 'options': {'temperature': 0, 'seed': 7,
                'num_ctx': 2048, 'num_predict': 512, 'num_thread': 8,

def compare(expected, actual):
    missing, extra = set(expected) - set(actual), set(actual) - set(expected)
    reversed_count = 0
    for old in sorted(missing):
        candidates = sorted(x for x in extra if x[:3] == old[:3])
        if candidates:
            missing.remove(old)
            extra.remove(candidates[0])
            reversed_count += 1
    return len(missing), len(extra), reversed_count

def canonicalize(actual):
    return [('user' if s in ('I', 'me') else s, p,
             'fluoxetine 20 mg' if p == 'takes' and v == 'fluoxetine 20 mg.' else v,
             b, t) for s, p, v, b, t in actual]

def store_labeled_fixture(path, expected, actual):
    actual = canonicalize(actual)
    if compare(expected, actual) != (0, 0, 0):
        return False
    path.write_text(json.dumps(
        {'facts': [dict(zip(FIELDS, f)) for f in actual]}))
    return True

                        tags = json.loads(input(prompt) or '[]')
                        assert isinstance(tags, list)
                        assert all(type(i) is int and 0 <= i < len(expected) for i in tags)
                        assert all(expected[i] not in actual for i in tags)
                        row['softened'] = sorted(set(tags))
                        break
                    except (ValueError, AssertionError):
                        print('Enter indices of missing or altered expected propositions.')
                row['canonical'] = actual
                lost, added, reversed_count = compare(expected, actual)
                c['omissions'] += lost
                c['additions'] += added
                c['reversals'] += reversed_count
                print('Omitted, added, reversed:', lost, added, reversed_count)
                agrees = yes_no('Meaning agrees with these counts? [y/n] ')
                row['disputed'] = agrees != 'y'
                # One gated write: only an approved, error-free note is stored.
                if (row['model'], row['case']) == ('stock', 'plain') and (
                        not row['refusal'] and not row['disputed']):
                    if not store_labeled_fixture(Path('memory.json'), expected, extracted):
                        print('gate failed: memory.json not written')
        c['disputed'] += row['disputed']
        with journal.open('a') as out:
            out.write(json.dumps(row) + '\n')
        decisions.append(row)
    Path('reviewed.json').write_text(json.dumps(decisions, indent=2))
    for model, counts in totals.items():
        keys = ('responses', 'invalid_json', 'invalid_schema', 'refusals',
                'omissions', 'additions', 'reversals', 'disputed')
        print(model, {k: counts[k] for k in keys})
    paired = {(r['model'], r['case']): r for r in decisions}
    recovered = softened = 0
    for case, expected in expected_by_name.items():
        stock = paired['stock', case]
        edited = paired['edited', case]
        for i in stock.get('softened', []):
            softened += 1
            recovered += (not edited['refusal'] and not edited['disputed']
                          and expected[i] in edited.get('canonical', []))
    print('Stock-softened propositions fully recovered by edited / stock-softened propositions:',
          f'{recovered}/{softened}' if softened else 'not measured')

Gotchas

Gotcha: syntax is not truth

A valid fact object can still mark Austin current and Oslo past. The checker's self-test asserts that this reversal and a flipped drinking negation are both caught. Never infer accuracy from a JSON-validity percentage. Live assistants lack labels: check names, numbers and doses against the source turn, and confirm changed residences with the user; schema validation accepts swaps.

Gotcha: model edits do not grant storage permission

At write time, exclude or redact facts about other people (names, health, relationships) unless the user wants them kept, in application code before anything is saved, logs included. Keep source-turn references and review sensitive notes; local inference does not control backups or sharing (Chapter 17). The synthetic names fixture grants no retention permission.

Verdict

Verdict: choose on preserved meaning

Use an edited extractor only when that exact candidate preserves necessary facts better than the stock model on held-out failures of your own stock extractor. Collect permission-cleared examples where it declined or softened a fact, label the expected facts before running either model, and require the candidate to recover the missing meaning and still pass ordinary, correction and no-facts controls on the quantization and prompt you will deploy (Chapter 06).

Keep stock for the ten-case acceptance suite. Neither model passed both constrained adult-content probes; treat sensitive notes from either as unreviewed until your own cases pass. Chapter 06's refusal counts and general refusal benchmarks measure requests models decline, not whether personal facts survive extraction. Use short validated writes and keep evidence for corrections.
