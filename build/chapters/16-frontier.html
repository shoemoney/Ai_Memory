Map of the frontier

Agent memory mostly uses files, vector indexes and graphs. Figure 1 maps twelve lines of research beyond them, grouped into six sections below.

Prototype in Figure 1 means open code that works in a lab, with no support promise, and Paper only means a published result with no code a team could adopt. Placement follows cited evidence; lines can occupy multiple columns.

Gotcha: results are mostly self-reported

Most figures are self-reported. An independent audit disputes LoCoMo’s reference answers (a long-conversation benchmark); its official issue thread records judge inconsistencies and acknowledged data-quality concerns (Chapter 17).74,1

Compute before the question arrives

Sleep-time compute, dreaming and offline consolidation

Sleep-time compute moves work off the query path. It anticipates questions and saves notes instead of rederiving them at query time.2 The authors report up to 2.5 times lower cost per query when several questions share one context. Tested locally (benchmarks/gap-reruns): a 7B model on 32 grade-school math contexts, 5 questions each. Arms: direct answers, notes for one question and notes shared across 5 questions, at different verbosity levels. Notes average 646 tokens per context. Weighted cost per answer = note tokens ÷ questions sharing notes + 10 × query-time generated tokens. The paper’s assumed tenfold cost for latency-optimized query tokens is a proxy here, not measured prices. Substitute your price ratio for spend estimates. Single-question notes cost 3.2 times shared notes with the tersest prompt, 1.1 with the most verbose. These ratios measure reuse, not savings over direct answering. Verbose notes lowered accuracy from 58.8% to 48.1% (difference -10.6 points, 95% interval -17.5 to -3.7). A/B consolidation against direct answers; shorten or skip notes if accuracy falls.

  • Shipped Letta. Version 0.7.0 added sleep-time agents: one talks to the user while another edits its memory blocks.3
  • Research preview Claude dreams (Managed Agents, access request needed). An asynchronous dream reads a memory store and 1 to 100 past session transcripts. It merges duplicates and replaces stale or contradicted entries in a new store. Inputs stay unchanged; outputs are discardable. A dream takes minutes to hours, is billed at standard token rates, and is not eligible for zero data retention or HIPAA.4
  • Anthropic's own measurements. A 6 November 2026 essay reports wikis built over 128 dreams lifted scores on 25 questions from 13% to 48% of graded criteria, and that wiki plus search scored 61% against 53% for search alone. On one task the wiki grew to 1.77 times the source token count with no clear accuracy gain. These are vendor measurements, not rerun here.5

Gotcha: a dream can promote a wrong note

Anthropic's essay warns that a wrong note promoted into the always-loaded layer enters every session, and that agents sharing one page overwrote each other's facts, leaving 41 of 57 facts intact until each agent got its own page.5 Review a dream's output before attaching it (write gates: Chapter 17).

Memory in weights and caches

Test-time memory: Titans and its relatives

Paper only (original release) Titans keeps attention as short-term memory and adds a small neural module that updates while the model reads.6 Google reports gains over Transformers and linear recurrent models across language, reasoning, genomics and time series, including needle-in-haystack tests beyond 2 million tokens.6 An independent reimplementation finds memory helps, but smaller chunks lose attention context and strain cross-chunk recall.7 Paper only Nested Learning studies learning processes that update at different rates, letting some learned state change while other state stays stable; its continual-learning proposal has no independent replication cited here.8

Self-updating pools, per-user edits and knowledge editing

Prototype, not run MemoryLLM adds a fixed-size memory pool inside the model's latent space that updates itself from new text. Its authors released code and a model, reporting no degradation after nearly a million updates.9

Paper only A June 2026 paper stores each user's facts as edits to a hash-keyed lookup table inside the model, with one small shared adapter that reasons over it. Its authors report that direct recall matches a separate low-rank adapter (LoRA) per user, with 5.6 times higher indirect-reasoning accuracy, and that edits from different users combine in one table; none of this was run here.10 If it shipped, per-user facts would leave the prompt and deleting one would mean editing weights.

Prototype, not run ROME edits one fact with a rank-one update to a feed-forward layer.11 This single-association edit does not establish per-user memory support; keep user facts elsewhere.

Looped transformers: compute is not stored knowledge

Shipped Inkling 2 Mini, released with open weights on 20 November 2026, runs its middle layers several times per token.72 In its variable-loop research checkpoint, Thinking Machines Lab reports better multi-step reasoning and long-context retrieval with more passes, but no gain on factual-recall tests. The maker says stored knowledge mostly tracks total parameter count.72,73 These are vendor claims, not reproduced here. Extra computation does not replace an external memory store; the maker says search and tools close the knowledge gap.72 Add retrieval when questions need facts absent from pretraining, whatever the loop count. Chapter 06 has its details and this book's one local test.

Cartridges: a trained KV cache per corpus

Prototype (run here) Train a small KV cache (attention state built from text) once instead of prompting with the corpus repeatedly. Self-study generates synthetic conversations about the corpus and trains the cache with a context-distillation loss (teaching it to reproduce the model's answers with the corpus in context); plain next-token training was not competitive with in-context learning.12 Stanford’s authors released code, reporting in-context quality with 38.6 times less memory.12 A short local training run (1.5B model, one patient’s records, 20 questions) did not match that. The cache cut stored attention state from 338.6 MiB to 5.75 MiB, but accuracy fell from 16/20 (80%) with documents in context to 6/20 (30%). The run does not test the full method. Code: benchmarks/param-reruns.

Cartridges suit stable corpora and trainable open-weight models. If new per-query cost reaches baseline cost, there is no break-even. Otherwise:

Break-even queries = preparation cost per corpus version ÷ (baseline minus new cost per query), in one currency. Preparation includes synthetic self-study and cache training. Before refresh, queries must exceed break-even and held-out quality meet your target.

Also not run: DeepSeek's Engram adds an N-gram lookup table inside the model, trained with the model, so it holds shared pretraining knowledge, not per-user memory.75 KVzip evicts low-importance KV-cache entries without knowing the query, so one compressed cache serves many questions. It needs no training, unlike Cartridges, and stores less than an uncompressed prompt cache (Chapter 10).76

Compressed context and recursion

Latent memory: MemGen

Prototype (run here) A reinforcement-learned trigger watches the model's reasoning and decides when a second module, the weaver, inserts latent tokens (internal vectors, not words). Authors report gains up to 38.22% over two external-memory systems and up to 13.44% over a baseline trained with Group Relative Policy Optimization (GRPO, an RL fine-tuning method) on eight benchmarks, none reproduced here.13 Tested locally: on 150 GSM8K (grade-school math word problems) test questions (benchmarks/param-reruns), the released 1.5B checkpoint scored 68.0% against 58.0% for the same model without the memory module, a gain of 10.0 points (95% interval 1.3 to 18.7). The implementation publishes weaver/trigger training, evaluation scripts and Qwen2.5-1.5B-Instruct and SmolLM3-3B checkpoints for KodCode, GSM8K and TriviaQA, with no production support.14

Recursive language models

Prototype, not run The model inspects a long prompt variable through code and calls itself on pieces. Authors report inputs about two orders of magnitude beyond the window and, on GPT-5, median relative gains of 26% over compaction and 13% over Claude Code at comparable cost; none rerun.15 Use a code sandbox and cap recursion depth and tokens. Start with offline inputs too large for one window; measure interactive latency against your response-time budget.

Memory the agent curates or carries

Agents store, link, rewrite and retrieve memory, sometimes trained with reinforcement learning (RL). Chapter 13 covers shipped frameworks; these gains are self-reported.

Start with an untrained playbook (ACE above; details below). Below: utility selection, hierarchical retrieval, evidence fallback, decay and learned state.

Runtime utility learning: MemRL

Prototype, not run MemRL targets repeated tasks with pass/fail checks, such as similar build failures. Two-Phase Retrieval selects similar episodes by learned utility score. Passing tests raise the retrieved episode's score, letting it outrank a similar failed attempt. Weights stay frozen. Authors report gains on HLE (hard knowledge questions), BigCodeBench (code generation), ALFWorld (household text tasks) and Lifelong Agent Bench (repeated agent tasks), none reproduced.22

  • Test it. Compare against retrieval over the raw history (RAG, Chapter 00) with the same model, task split and budget, measuring held-out repair success, tokens, latency and verifier errors.
  • Cost. Feedback needs test execution, environment interaction or a judge call on top of the reasoning and summary calls; frozen weights remove fine-tuning, not these costs.22,23
  • Risk. The paper's appendix G.4 warns that false-positive rewards can give bad episodes high utility and spread contaminated behavior. Keep the verifier independent of retrieved text, audit rewards and be able to remove poisoned episodes.22

Hierarchical retrieval: xMemory

Prototype, not run xMemory separates interaction history into events and reusable memory components, then groups related components. Retrieval selects complementary groups and expands to original messages only when needed, avoiding redundant flat top-k results and details lost in summaries. Authors report better answer quality and token efficiency on LoCoMo and PerLTQA (personal long-term question answering); official code is available. For near-duplicate support conversations, test update separation against flat retrieval.25,26

Compact notes with a route back to evidence: TierMem

Prototype, not run TierMem (COLM 2026, MIT license) keeps two linked tiers: compact summaries and extracted facts, and original interaction pages. A trained Qwen3-0.6B router checks retrieved notes for enough evidence. Otherwise, bounded retrieval follows source links to raw pages; note updates preserve those links. A lighter variant called Jev in the repository uses Markdown notes and searchable raw history, with no router training or vector database.27 Test: from a debugging session, store the timeout in a note and the failing test’s name only on its linked raw page. Ask for the timeout: require a note-only answer. Ask for the test name: require a page fetch and the correct name.

Soft forgetting without erasure

Prototype, not run Vestige’s maintainer advertises FSRS-6 (a spaced-repetition scheduling algorithm) memory decay for retrieval, a claim with no independent evidence of better answers.28 Test: toggle decay on a fixed corpus at fixed top-k. Require rare-critical-fact recall not to fall; report answer accuracy for those facts and recent trivia. Soft forgetting in Chapter 05 covers the scoring and its risk to rare facts. A low score cannot replace hard expiry or required deletion (Chapters 10 and 17).

Learned internal state: MEM1 and MemAgent

Prototype, not run MEM1 trains memory consolidation and reasoning together with RL: each turn merges new observations into a compact internal state and discards irrelevant history. Authors release training code, reporting gains on retrieval QA, web QA and shopping tasks.30 MemAgent reads document segments, overwrites working memory repeatedly and publishes RL training and inference code.31,32 Unlike playbooks, both carry state within one task and need training; neither replaces a per-user fact database.

Start with a playbook

Prototype (local attempt invalid) A playbook is a small text file the agent edits in place; ACE and Dynamic Cheatsheet authors report gains without training. Dynamic Cheatsheet keeps an evolving cheatsheet for a black-box model, and its authors report GPT-4o on Game of 24 rising from 10% to 99%.33 Local 3B run on the same 100 public puzzles was invalid: most cheatsheet answers hit the output-token limit (benchmarks/small-reruns). It does not test the GPT-4o gain. A playbook costs prompt tokens on every call; a wrong rule loads every session (write gates: Chapter 17).

Learned write policies: Mem-alpha

Paper only Mem-alpha instead trains the agent by RL to decide what to store, on histories up to 30K tokens.34

Context, skills, long windows and memory systems

Context engineering, editing, compaction and the memory tool

Shipped Usable today: the memory tool is generally available. Beta Context editing and compaction are beta. Anthropic defines context engineering as curating the tokens available at inference time.35 Its memory tool needs {"type": "memory_20250818", "name": "memory"}, and your application stores the files.36 Context editing clears old tool results and thinking blocks by rule and is in beta behind the header context-management-2025-06-27.37 Server-side compaction replaces older turns with a summary Claude writes. Compaction runs on demand or at a token threshold.38 Chapter 01 shows the memory tool's file layout.

Long context versus retrieval, and context rot

Chroma tested 18 models, including GPT-4.1, Claude 4, Gemini 2.5 and Qwen3, and found reliability falls as input grows, even on a trivial repeat-the-text task.39 A re-evaluation of long context against RAG finds long context generally scores higher on question answering, summarization-based retrieval comes close, and RAG has advantages on dialogue-based and general queries.40 A February 2026 study found that repository context files tend to lower task success compared with no context file.41 Full context is the baseline to beat when the history fits the window, accuracy on your own questions holds as history grows, and you can afford the tokens. Past that, retrieve, and keep the always-loaded layer to what every session needs.

Unverified: a 113K token cliff

Secondary blogs quote a degradation point near 113K tokens. Chroma's report does not contain it, so treat it as unconfirmed.

Net value against raw-history RAG: Memory Tax

Paper only Memory Tax (October 2026) calls gains over raw-history RAG memory benefit and losses memory tax, because reorganizing history can remove evidence. Its authors find dedicated memory systems underperform RAG in many cases, though not every workload.42 Compare against raw-history retrieval on the same history, reader and questions.

Tested locally: correct answers on LoCoMo: full context 71/123 (58%), Mem0 66/123 (54%), plain RAG 62/123 (50%), Graphiti (temporal knowledge graph, Chapter 14) 44/123 (36%); on LongMemEval (multi-session chat-history questions): BM25 (keyword ranking, Chapter 05) 191/300 (64%), dense retrieval 165/300 (55%). Intervals and limits: Chapter 17; code: benchmarks/locomo and benchmarks/longmemeval. Mem0’s 4-answer lead over RAG is inconclusive at this sample size; Graphiti trails RAG by 18, consistent with Memory Tax.

Procedural and skill memory

Shipped A skill (format in Chapter 01) is a folder with a SKILL.md file and optional scripts, loaded when relevant, so only its short description costs context until then.43 On 22 October 2026 Anthropic donated the open standard to the Agentic AI Foundation under the Linux Foundation, saying more than 70 agent platforms had integrated it.44 Skills have three authorship models. Human-written skills are standard. Agent-written skills start with research such as Voyager, a Minecraft agent that kept a growing library of executable skills,45 ACE above, and Agent Workflow Memory, which induces reusable workflows from past trajectories.46 Reviewed skills are agent-written skills that a person approves before they load. No product read here documents that review step.

Beta memU offers automatic skill authorship in beta. It is an Apache-2.0 open-source project at version 0.11.0-beta.3 and installs scheduled tasks for Codex, Claude Code, Cursor and other hosts. They slice new session logs into jobs, and the host agent decides to do nothing, patch a skill or create one. The skill is saved as Markdown, embedded by name and description and retrieved on similar tasks.47 Its service makes no model calls, so skill writing costs your own agent sessions, and its steps include no human review.

Memory operating systems

Prototype, not run MemOS and MemoryOS manage memory as schedulable tiers. Both report state-of-the-art LoCoMo results.48,49 Mem0, the shipped library (Chapter 13), reported a 26% relative gain over OpenAI's memory in its 2025 paper.50 Neither LoCoMo headline result nor Mem0's OpenAI comparison was reproduced here; the local Mem0 run above uses different comparators. Before adoption, compare raw-history RAG and full context on your questions as above.

MemOS's research design differs from MemOS 2.0's self-hosted REST service (Neo4j and Qdrant) and local SQLite plugins (Chapter 13).51

Sharing, benchmarks and attacks

Multi-agent shared memory

Paper only A June 2026 paper names four failure modes for fleets of agents sharing memory (leakage, stale propagation, contradictions that persist, lost provenance) and proposes scoped retrieval, temporal supersession, provenance tracking and policy-governed propagation. Authors tested these in one production multi-tenant service, MemClaw, without a baseline; a direct-read scope bypass was fixed during the study.52

Portable memory between harnesses

Paper only Memoryfields proposes Markdown pages with optional YAML metadata and a rebuildable vector index.53 Universal Memory Protocol (UMP) proposes transport-neutral records with scope, provenance, validity and recording times, optional signatures, and revision and forgetting operations. Both are proposals.54

Migration to test. Export one user’s memory between agent harnesses (runtimes hosting agents, such as Claude Code) and back, keeping source ids, scope, validity times, provenance, supersession links and deletions. Check that an expired fact stays expired, a deleted fact stays absent, another user's record stays inaccessible, and vectors are rebuilt for the destination model.

New benchmarks

Prototype (full-context arm run) MemoryAgentBench tests accurate retrieval over incremental input, test-time learning, long-range understanding and selective forgetting across turns; its authors report that no method masters all four.57 Tested locally: on 150 paired questions from the five smaller histories, a local 14B model with 4-bit quantization scored 95.3% with full context (95% interval 90.7 to 97.7). No RAG comparison is reported: 111 of 150 questions exceeded the encoder’s token limit. Histories, reader and chunking also differ from the paper. Code: benchmarks/membench. Prototype (code run) BEAM has 100 conversations up to 10 million tokens and 2,000 validated questions, and reports that 1 million token models degrade as dialogues grow, with or without retrieval.55 Counts were verified and BEAM code run on 100 questions (LIGHT below); degradation was not reproduced.

Prototype (run here) LIGHT, the architecture paired with BEAM, combines an episodic index of the full conversation, recent-turn working memory and a salient-fact scratchpad. Each turn, a model extracts index keys, a summary and scratchpad notes; questions trigger dialogue retrieval and scratchpad filtering. BEAM’s authors report gains of 3.5% to 12.7% over their strongest baselines by backbone, without specifying relative or point units. Tested locally: BEAM's own code, run on 100 questions with a 3B local model, put LIGHT at 31% against 35% for plain retrieval on BEAM's rubric score (difference -4 points, 95% interval -12 to +3), so the gain did not appear at that size (benchmarks/gap-reruns). Indexing, note updates and compression cost model calls before questions arrive, and filtering adds query-time calls.55 Compare against raw logs plus recent context, counting preprocessing/query tokens, latency and accuracy.

Prototype (QA attempt invalid) HaluMem (EMNLP, October 2026) evaluates hallucinations at three stages: memory extraction, updating and memory question answering. Its authors release resources and report hallucinations accumulating during extraction and updates.58,59 Tested locally: a question-answering-only attempt on 150 questions was abandoned: the local 14B judge matched a hand check on only 28 of 41 answers and privacy masking altered ordinary words in 12 questions; validate masked questions against originals, then check a replacement judge against hand labels before scoring (benchmarks/membench). Inspect the stored record, retrieved evidence and final answer to locate failure. A task-success check shows whether it changed the outcome (Chapter 17).

Prototype, not run Chapter 04 covers embodied ConceptGraphs memory: a 3D object map and scene graph.56 WorldMemArena (May 2026) tests agents that see and act, with 400 multi-session multimodal tasks and gold evidence chains that locate a failure in writing, maintenance, retrieval or use. Authors report poor use of visual evidence. The repository (MIT license per its README) runs 19 baselines and needs a 10 GB download.60,61

Benchmarks that score actions. A recall benchmark asks the agent to reproduce a stored fact; three newer suites test whether memory changes its actions.

  • MemoryArena (arXiv February 2026, revised September 2026) gives agents interdependent multi-session tasks in web navigation, planning, information search and formal reasoning. Its authors report that agents near saturation on LoCoMo perform poorly there; this book ran no action tasks and did not reproduce that.62
  • DolphinBench (September 2026) has three knowledge-work personas of about 500K tokens of user messages each and 200 tasks per persona. Each task fails without the history and passes with it, and submissions report cost and latency. It is hosted under Mem0's GitHub organization and two authors also wrote the Mem0 paper, so weigh any Mem0 comparison accordingly.63
  • STATE-Bench (Microsoft, 19 May 2026, MIT license) has 450 customer-support, travel and shopping tasks scored against deterministic end-state checks, five runs per task, a pass^5 reliability score (a task counts only if all five runs pass) and cost per task. Microsoft reports that GPT-5.1 without memory completes fewer than half of the tasks reliably. The official protocol needs a hosted simulator and judge, so that claim was not reproduced.64

Coding memory: Hy-Memory, CMB and diff chains

Prototype, not run Hy-Memory (self-hosted SDK, Apache-2.0) stores a chat hierarchy, working facts and coding diff chains; test it when coding tasks resume across sessions or branches. Its coding pipeline links facts and reusable experiences to revision diffs, preserving changes later reverted from the working tree (Chapter 06 covers its writer model). Its model card pins retrieval and reader settings and uses fixed 20% subsamples. Its CMB (Coding Memory Benchmark) column averages two repository question-answering evaluations; do not compare it with the code-editing resolved rates below.29,65

The September 2026 CMB paper, linked by the official repository as an ICLR 2027 submission, evaluates 216 executable code-editing tasks and 750 diagnostic questions across nine repositories, replaying the same frozen histories for each memory method. Resolution requires a nonempty patch, valid test report, and passing new and regression tests. Reported by Tencent's authors, not run here: their TriLink method links facts, experiences and diffs. The public release lacks frozen tasks and grading files, preventing verification.66

Figures from the paper (results tables, source 66; DeepSeek v4-flash): TriLink resolved 35.6% of tasks against 28.2% for MemOS (tied with FullContext) and 26.9% for RAG, and scored 64.2% on QA against 62.2% for RAG. With Claude Sonnet-5, TriLink resolved 43.1% against 36.6% for Mem0.

Check both evidence recovery and repository tests. The QA score counts judge-matched reference requirements and the resolved rate counts finished edits, so on these figures RAG is within 2 points of TriLink on QA but 8.7 points (about 19 of 216 tasks) lower on resolved tasks. Limited scale and no significance test make the gap suggestive.66

Memory attacks

MINJA67 and AgentPoison68 are early papers on attacking agent memory, building on older retrieval-poisoning work, and defenses are early. Chapter 17 holds the threat model, rates and controls. Two newer attacks follow.

Prototype (run here) InjecMEM (COLM 2026) needs one chat turn and no access to the store.69 An anchor supplies topical cues for retrieval; a short adversarial command found by gradient-based search steers the answer once retrieved. The authors report reliable topic-conditioned retrieval with unrelated queries unaffected.

Tested locally: a 7B-family payload in a 3B toy store was retrieved in 0/100 trials with defenses and 0/100 without. This undiagnosed retrieval miss leaves steering unmeasurable and neither confirms nor refutes the paper (setup and limits: Chapter 17; benchmarks/security).

  • Limits. The strongest version needs white-box access to a model, a command tuned on some model families can fail on a held-out family, and systems that summarize before storing need a different attack.
  • Defense code. The repository screens text with a small judge model, a perplexity check, Llama Prompt Guard 2 or a ProtectAI classifier, at initialization, on writes or on retrieval (default: retrieval only).70 If your tests support it, screen at both write and read. In the local test the prompt write reviewer (a local model screening proposed writes) rejected all 100 benign factual writes (from ten templates), so a defended success rate of zero does not show the screening is selective.

Prototype, not run SkillJack (August 2026) attacks the step that turns experience into skills, where the agent's own extraction rewrites a poisoned experience into a skill. The authors name three properties: extraction hides malicious intent, a transient experience becomes a persistent capability, and the skill survives deletion of its source records.71

  • Reported figures. On two research systems, SkillX and Anything2Skill, with 150 trajectories, safety detection fell from 98.5% on the poisoned trajectories to 11.4% on the extracted skills in SkillX. Attack success was 56.2% on SkillX and 89.2% on Anything2Skill, and 80.0% of skill-mediated attacks persisted after the original records were deleted. These author-reported figures concern systems other than memU; nothing reproduced.71
  • What to do. Link learned skills to sources and require approval before loading. On source revocation, block dependent skills at once and restore only reviewed, reapproved versions (Chapter 17).

Usable today

Use now, safest first:

  • Memory tool (generally available), context editing and compaction (beta; expect header and field changes).
  • Agent Skills. An open, broadly supported format (Chapter 01). Agent-written skills (memU, beta) need a review step you add yourself.
  • A consolidation pass. Letta sleep-time agents ship, Claude dreams are a preview, and a home-built merge-and-prune job works too (Chapter 02; guardrails, Chapter 17).
  • Mem0 or Letta. Maintained libraries (Chapter 13), with vendor benchmark claims. Pick Letta for agent-edited memory blocks via tools; pick Mem0 for application code to extract and retrieve facts around each turn.
  • An agent-edited playbook. ACE needs no training. Gate writes, version files, prune rarely used rules, and measure token cost against accuracy.

Test in a lab only. Prototype implementations are lab candidates. Before production, compare held-out application tasks against no memory, raw-history retrieval and, where it fits, full context, within write-cost and latency budgets. MemoryArena and DolphinBench are secondary checks (weigh DolphinBench’s Mem0 ties); STATE-Bench needs its hosted simulator and judge. None was run here (Chapter 17).

Wait for production. Every Paper only artifact, including original Titans, per-user edits and Nested Learning. ROME is a single-fact-editing lab prototype, not a user-fact store. The independent Titans reimplementation has chunking limits described above.

Open problems

  1. Saturated, self-reported benchmarks. LoCoMo's reference answers are disputed (Chapter 17), few papers test MemoryAgentBench and BEAM together, and a memory vendor runs one action suite.
  2. Amortization. No published cross-workload break-even figures; see the Cartridges rule.
  3. Weight memory. No independent evidence of robustness to conflicting updates.
  4. Attacks. Authors report single-turn injection (payload tuning may need white-box model access) and poisoned skills surviving source deletion; neither was reproduced here.
  5. Deletion. Deletion propagation to weights, caches, summaries and derived skills is unsolved.
