Retain, recall, reflect
Retain saves a note; recall fetches related notes; reflect reasons over them. Wide recall fetches notes with a high budget; its unit and value were not logged.

You will need: HNSW and IVFFlat, approximate nearest-neighbor indexes (Chapters 08 and 11); rank fusion and rerankers (Chapter 05).

System 1: flat files with an index

Projects have Markdown notes with one-line index entries; counts and arrival rates are unknown. A global file loads hard rules at session start; procedures load when needed; facts go to the wiki.1 Chapter 01 covers mechanics. No service runs; curation depends on System 2.

System 2: a wiki compiled from the files

Agents maintain Git-tracked Markdown pages under a schema, with an index, append-only log, types, dates and sources.1 Chapter 02 describes the pattern. A script lists changed or new notes. An agent compiles their facts into pages and marks each note handled in a separate ledger, leaving the source untouched. A checker validates metadata and links.1 At the last read, 1,177 of 1,424 source notes awaited compilation; read date, accumulation period and cause are unknown.1

Unverified: the counts do not reconcile

The operator reports 257 compiled entries; 1,424 minus 1,177 is 247. The unexplained gap of 10 leaves roughly five sixths pending.1

System 3: a framework with a local note-taker

Each assistant’s framework starts PostgreSQL and maintains its memory bank (store). A local LLM extracts chat facts on an Apple Silicon Mac. Model: about 9 billion parameters, about 5 GB quantized, reasoning off; valid-JSON fact-extraction test passed.1

B replaced reflect’s synthesis with wide recall’s notes, shifting reasoning into its context. A recall and B wide recall are not proven equivalent. Compare note overlap and answer quality on identical banks and prompts.

Three traps

Gotcha: ids that collide within one second

Parallel saves collided on framework-generated clock-second note ids. Check omitted-id generation. Persist unique ids per logical save; reuse on retries. Verify retries leave one note: replacement, ignored retry or conflict (Chapter 17, queued writes). Corrections need new ids; recommendation: link predecessors, exclude superseded notes from current-fact recall.1

Gotcha: the gateway dropped system messages

B’s gateway removed system messages before the model, including memory instructions. Those moved to a preserved field; compare sent and model-bound requests. Unprompted saves and fresh-session readback confirmed storage and retrieval, without proving instruction delivery.1

Gotcha: a changed prefix loses the cache

The note-taker’s server caches identical tokenized prefixes (first token: cold 0.776 s, repeat 0.165 to 0.232 s). Its client keeps the system message unchanged and first.1

System 4: PostgreSQL search

PostgreSQL with pgvector searches a fixed corpus. Queries filter by the pinned hosted embedding model and size (1,536 dimensions), excluding other models even at equal size. Changing models requires re-embedding all rows.1 Chapter 08 covers this stack.

One SQL statement filters both branches by model, dimensions and kind (record category). Semantic search keeps the nearest 40 passages by cosine distance; lexical search ranks by full-text score, cutoff unrecorded. Reciprocal Rank Fusion combines them with constant 60. The final limit defaults to 6, configurable from 1 to 20.1 Chapter 05 explains the technique. A 26 September 2026 count found 3,245 active documents and 7,668 passages.1

Finding one: the semantic branch had no approximate index

The 26 September 2026 audit rated missing approximate indexes "Severe": three tables used bare vector columns without HNSW or IVFFlat, computing distances exactly. Exact search loses no recall through approximation. Without measured query cost, the rating establishes no current bottleneck.1

The proposed migration adds partial HNSW expression indexes to two tables (cosine, m=16, ef_construction=64). For 1,536 dimensions, use a dimensioned cast in index and query ordering, or constrain the column dimensions. A partial index holds filtered rows; PostgreSQL must prove the query requests only those rows. Match its predicate and dimensioned expression in the query. The third table stays intentionally unindexed, reason unknown. The migration was unrun on 27 September 2026; later deployment is unconfirmed.1

Finding two: a miss with incomplete diagnostics

One query missed its correct passage: rank 159 of 1,905 lexically and 1,063 of 7,668 semantically. Its lexical-only fusion score, at most 1/219, trails all 40 semantic hits (at least 1/100 each), excluding it from the final results regardless of lexical cutoff. That cutoff decides whether a reranker could see it. A replay’s 30-fold widening and rank 240 lack branch labels. Log both ranks and cutoffs, fusion rank and final limit to distinguish pool exclusion from low final rank. An untested proposal reserves merged-pool space for unique headings in document front matter.1

What to do differently

  1. Track the inbox as a metric. Schedule compiles from day one. Set a publication freshness target; alert on oldest pending age and compare arrivals with completions.
  2. Inspect, then test end to end. Check model-bound instructions and roles, then test unprompted retention and fresh-session recall.
  3. Record cold start and idle behavior next to recall time.
  4. Audit the vector index. Inspect the deployed index and EXPLAIN the real query, including partial-predicate implication. Time representative searches. EXPLAIN (ANALYZE, BUFFERS) executes the statement; use it on read-only searches. A scan may mean a missing or skipped index, or the planner’s correct choice for a small table. Keep exact search if it meets the budget.
  5. Measure candidate rank before adding a reranker. It cannot reach a passage outside the pool.

Verdict: start with one system

Start with flat files. Add a scheduled wiki for curation backlog, a framework for extracting chat facts, or PostgreSQL search for a fixed corpus. Only the wiki builds on the files. Measure backlog age, answer latency and candidate misses before adding systems (Chapter 18).
