Text embeddings

A model turns text into numbers so a program can find it by meaning.

Maturity

Shipped

Setup effort

2 of 5

Running cost

1 of 5

Best for

Anyone whose agent must find notes by meaning, on a CPU-only box or through a hosted API.

What it is

An embedding is a model-computed number list for finding notes by meaning: a search for "the tax thing from March" can land on a note that says "quarterly filing", although the two share no words.

Similar meanings point in similar directions; the program compares texts by their angle (cosine similarity; a smaller angle scores higher).

The list is a vector; dimensions count its entries: 1,024 dimensions means 1,024 numbers per text. The two smallest models tested, bge-small-en-v1.5 (bge-small below) and all-MiniLM-L6-v2 (MiniLM below), return 384, and the largest Qwen3-Embedding model returns 4,096.1

The model neither answers nor remembers; the vector store holds memory (Part D). Images: Chapter 04.

Terms new in this chapter

MTEB
An embedding benchmark suite with several versions.
nDCG@10
Normalized discounted cumulative gain at 10 rewards ranking relevant results near the top. Scores here are the usual 0 to 1 value times 100.
Matryoshka (MRL)
Training that makes a vector’s first k numbers usable alone.
Scalar and binary quantization (of stored vectors)
Shrinking vectors with 8-bit integers or single bits.
Prefix
A short instruction placed before the text, which some models expect on queries, documents or both.

How it works

Save each chunk beside its embedding. Recall it by embedding the question with the same model and fetching the nearest vectors. Most models read the whole text at once: each token reflects words before and after it. They pool (combine) token vectors, usually by averaging; the model card specifies how. Some, such as Qwen3-Embedding, read left to right and take the last token's vector, which has seen the whole input. Servers may ask for a pooling mode (step 5).

Chunk at paragraph or heading boundaries near 300 tokens to balance precision and prompt cost, or at the model’s lower context limit; MiniLM truncates at 256 tokens. Overlap only when sentences often cross a boundary. Record chunking and token limits as corpus metadata.

Dense, sparse and multi-vector

Almost every model here is dense. BGE-M3 can produce all three kinds.2

KindWhat is stored per textWhat it is good at
DenseOne fixed-length floating-point vector.Meaning matching by nearest-neighbor search, usually cosine. Smaller than multi-vector storage.
SparseA weight for each vocabulary term the text uses. Size depends on non-zero term count and index encoding.A learned keyword index; rare exact terms still match.2
Multi-vectorOne vector per token. Each query token is scored against its best-matching document token and the scores are summed (late interaction, MaxSim).Better recall on long, detailed queries. At equal dimensions and precision per vector, storage grows roughly with the token count.2

pgvector 0.8.7 stores a dense vector in 4d + 8 bytes and a sparse vector in 8n + 16 bytes, where d is the dimension count and n the number of non-zero weights. At d = 1024, a sparse vector is smaller for n ≤ 510 non-zeros (8n + 16 < 4104; equal at 511). With 100 non-zeros it takes 816 bytes against 4,104. Sizes exclude table and index overhead.3

Matryoshka truncation

Matryoshka lets you keep 256 of 1,024 dimensions at a small quality cost. Jina v5 small supports sizes spanning 32 to 1,024; use a listed size.5 The EmbeddingGemma 2 card reports its MTEB English score falling from 68.46 at 768 dimensions to 67.78 at 256 (0.68 points lost for a third of the size) and to 65.68 at 128.7 Tested: on these three tasks, cutting EmbeddingGemma 2 from 768 to 256 dimensions cost 2.36 nDCG@10 points (95% interval 1.78 to 2.97): a mean of 60.73 fell to 58.37. The published figure averages the whole English suite.

Code will slice any vector, so cut only a model trained for it, to card-listed sizes; re-normalize afterwards.

int8 and binary quantization

Scalar int8 keeps one byte per number and binary keeps one bit. Jina says its v5 vectors survive binary quantization.5 Recall loss depends on the model and data; this book has no measurement of it. Compare float32 and quantized retrieval on identical held-out questions and corpus. Count answering notes in the top k chunks your agent reads; accept only tolerable loss. Top-10 overlap shows changed rankings but is not the acceptance test. With binary, fetch 10 times more candidates (an unsourced starting estimate; measure) and rescore with float32 or int8 vectors. Fit int8 ranges per dimension on a representative sample, save them with a calibration ID and reuse them for every later write; changing them means requantizing.

Query and document prefixes

Asymmetric models embed questions and passages differently. Omitting a prefix silently lowers quality. Ollama's documentation does not say it adds one, so add it in separate query and document functions.23

  • Qwen3-Embedding expects a task instruction on the query side. Its card says instructions typically add 1 to 5 points and recommends writing them in English.1
  • The EmbeddingGemma 2 card says omitting its prefix still works but lowers precision, and that prefixes apply to text only.7

When vectors can and cannot be compared

Compare matching models, revisions and preprocessing. Separate coordinate systems remain incomparable despite equal dimensions. bge-small-en-v1.5 and all-MiniLM-L6-v2 both return 384 dimensions, so a store takes either, yet the walkthrough scored one sentence across both at 0.2608, a plausible number with no meaning.

Two exceptions apply. A model trained with distinct query and document prefixes expects that difference: use each prefix as its card specifies (see Query and document prefixes).1,7 Two vendors also document shared family spaces:

  • Voyage states that all embeddings from its 4 series are compatible, so a large model can index and a lighter one answer queries.12
  • Cohere states that embed-v5.0-pro and embed-v5.0-fast share one space, and recommends indexing with Pro and querying with Fast.17

For shared families, record the space identity and models separately; this lab checks one model. Otherwise treat the model name, revision, prefix, cut length (Matryoshka dimensions kept), quantization and, for int8, the calibration ID as one identity recorded beside every vector. Search quantized vectors only with the scoring the store documents for that format: for binary vectors (one bit per dimension; step 6), Hamming distance (counting differing bits), never float cosine on the packed bytes.

Re-indexing

The identity identifies stale vectors. A supported Matryoshka cut needs no model call on saved full-precision vectors: slice, re-normalize and rebuild the store's index. Otherwise, changed spaces or document preprocessing require re-embedding every chunk. A change to the query instruction alone leaves stored vectors valid: version it and retest retrieval. To re-embed:

  1. Build a second index; preserve the old one.
  2. Embed every chunk again at the first ingest's cost: 1 billion tokens is about $20 on text-embedding-3-small and about $130 on text-embedding-3-large.15,16 For a local model the cost is wall-clock time.
  3. Pause writes before backfilling, or use a snapshot and replay writes, edits and deletions through a recorded cutover point. Check coverage, compare real questions on both indexes, switch reads and retain the old index. During the rollback window, apply writes, edits and deletes to both with their respective encoders, or log changes and catch up the old index before reverting. A deprecated hosted model forces it.

Good for and not for

Good for

  • Finding a note by its meaning when the question shares no words with it.
  • Checking a new memory against stored ones before writing, to avoid duplicates.
  • A corpus of thousands of chunks on a CPU-only machine.

Not for

  • Exact strings such as error codes: use a keyword or sparse index (Chapter 05).
  • Choosing the current fact by similarity alone: filter on validity dates or a superseded flag first (Chapter 14).
  • A commercial product built on a non-commercial license, or a setup that cannot record the model identity next to each vector.

Use cases

1 8,000 blog passages on a mini PC

Situation
A writer searches eight years of posts: 8,000 passages on a CPU-only PC.
Why it fits
At 1,024 dimensions, vectors fit in memory: 32.8 MB float32 or 8.2 MB int8. Qwen3-Embedding-0.6B embedded 6 short notes in 1.17 seconds on 4 CPUs (Numbers): about 26 minutes for 8,000; real passages are far longer, so plan for hours (estimate) and time 200 first.
Pair with
SQLite or pgvector for storage (Chapters 12 and 08), and a reranker from Chapter 05.

2 Personal notes search

Situation
A few thousand personal Markdown notes need meaning-based search, as in the opening filing example.
Why it fits
MiniLM returns 384 numbers per chunk with a few sentence-transformers lines.10
Pair with
Chapter 01 flat files for the notes, and grep for exact words.

3 Deduplicate memories before writing

Situation
An agent saves "User lives in Paris", then "The user is based in Paris". Near copies accumulate.
Why it fits
Embed each new memory and find its nearest neighbor (one call per write). Before merging, check entity, claim, polarity and time, since "User no longer lives in Paris" is a near match to keep. Set the threshold on labeled pairs; the walkthrough's question-to-note scores (0.7480 and 0.6636) only show that related text stays well below 1.0.
Pair with
A memory framework (Chapter 13) and a small model that decides merge or keep (Chapter 06).

4 Support docs in several languages

Situation
A team keeps help articles in English, Spanish and Japanese, and users ask in any of them.
Why it fits
Qwen3-Embedding has multilingual MTEB scores; BGE-M3 also offers sparse output.1,2 One index holds all languages; cross-lingual retrieval (Japanese questions finding English articles) remains untested. Check your pairs.
Pair with
Hybrid search with a keyword index, from Chapter 05.

Scope and scale

Vectors cost no context tokens; only retrieved chunks do. A write is one embedding pass per chunk, with no generation call; a read is one pass plus the tokens of the top results: five chunks of 300 tokens add about 1,500 prompt tokens (estimate).

No source gives a maximum count for scanning every vector (brute-force search). Check scan latency against your read budget and embedding throughput against your write rate.

  • Scan latency. Storage grows linearly (Chapter 00 sizing reference). At 1,024 dimensions, 10,000 memories take 41 MB as float32 and 100 such users take 4.1 GB, a million vectors. At an assumed 10 GB/s, reading an isolated 41 MB user partition takes at least about 4 ms; reading all 4.1 GB takes at least 0.41 s (estimates). Time the actual filtered query, including scoring.
  • Embedding throughput. Ten agents writing 20 chunks per second need 200 sustained. Measured: 373.1 texts per second (bge-small, 2 CPUs) and about 5.1 per second (Qwen3-Embedding-0.6B through Ollama, 4 CPUs), both on short texts; 300-token chunks will be slower. Replay your own chunk lengths.

Move to a store with an index (Chapters 08 or 11) when a scan misses your latency budget, to Chapter 05 when exact terms matter, and to Chapter 14 when facts change.

    set -euo pipefail
wait_http() {
  local name=$1 url=$2 payload=${3-}
  for attempt in $(seq 1 120); do
    if [ -n "$payload" ]; then
      if curl --fail -s --max-time 5 -H 'Content-Type: application/json' \
          -d "$payload" "$url" > /dev/null; then return 0; fi
    elif curl --fail -s --max-time 5 "$url" > /dev/null; then
      return 0
    fi
    sleep 1
  done
  docker logs --tail 40 "$name" >&2
  echo "STOP: readiness timed out: $url" >&2
  return 1
}

def post(url, payload):
    req = urllib.request.Request(
        url, data=json.dumps(payload).encode(),
        headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=300) as r:
        return json.load(r)


def check_record(rec):
    for key in RECORD:
        if key not in rec or rec[key] != RECORD[key]:
            action = ("validate query configuration before searching"
                      if key == "query_prefix" else "re-index before comparing")
            sys.exit(f"STOP: {key} differs: {action}")


def embed(kind, texts, rec=None):
    port, path = ROUTES[kind]
    url = f"http://127.0.0.1:{port}{path}"
    if kind == "ollama":
        with urllib.request.urlopen(
                f"http://127.0.0.1:{port}/api/tags", timeout=30) as r:
            tags = json.load(r)["models"]
        digest = next((m["digest"] for m in tags if m["name"] == rec["model"]), None)
        if digest != rec["revision"]:
            sys.exit("STOP: live model revision differs: re-index before comparing")
        return post(url, {"model": rec["model"], "input": texts})["embeddings"]
    if kind == "tei":
        return post(url, {"inputs": texts})
    return [d["embedding"] for d in post(url, {"input": texts})["data"]]


def timed(kind, texts, rec=None):
    t0 = time.perf_counter()
    vecs = embed(kind, texts, rec)
    return vecs, round(time.perf_counter() - t0, 4)


def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    return dot / (math.sqrt(sum(x * x for x in a)) *
                  math.sqrt(sum(y * y for y in b)))


if sys.argv[1] == "write":

Gotchas

  • EmbeddingGemma 2: avoid float16 (Local models).
  • A missing prefix can silently lower precision (Query and document prefixes).
  • Equal dimensions do not make cross-model cosine meaningful (When vectors can and cannot be compared).
  • TEI defaults to at most 32 texts per request (step 4).

Gotcha: the context claim differs by source

The Qwen3-Embedding card gives 32,768 tokens; Ollama’s 4b tag differs at 40K (0.6b shows 32K).1,25 Count prefixed tokens; obey documented and server limits. Test retrieval before relying on extensions.

Unverified: open questions

  • Current MTEB No. 1 and GPU/Mac speed.
  • Cohere embed-v5.0 and official embed-v4.0 prices; EmbeddingGemma 300M license (gated card).

Verdict

Verdict: small, local, labeled

Follow Picks by situation: Qwen3-Embedding-0.6B handles occasional writes, about 5.1 short notes per second on 4 CPUs.1,25 For throughput or tight storage, test bge-small’s held-out recall. Record vector identity; check recall before int8 (Chapter 17).

For multilingual GPU work, time 200 representative chunks before choosing 4B/8B; GPU throughput remains unmeasured. Add keyword search and a reranker for exact terms (Chapter 05). Chapters 21 to 23 use 1,024-dimensional Qwen3-Embedding-0.6B notes for a painter, doctor’s office and homebuilder.
