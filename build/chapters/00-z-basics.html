Memory basics: four kinds, one loop

Memory supplies context, saves facts during or after a turn, or changes model weights.

Reading time

About 20 minutes

Assumes

You have called a chat model API

You get

A shared vocabulary, three design questions, a quick-pick table and sizing formulas

Best for

Anyone choosing a design.

Why a model needs memory

The context window limits input and output per request: text and, on some models, images or audio. Fixed weights retain training knowledge, but recalling a past conversation requires the harness (the program running the model) to supply it again.

Memory supplies information or preserves what a turn produced, during it or afterwards: text, records or weight changes. Anthropic calls curating the tokens available at inference time context engineering;1 in this book's terms that is mostly the read path. Claude Code loads instruction files "at the start of every conversation".2

This book judges each design by what reaches the window, its cost in calls, tokens and time, and how it scales with users, memories and concurrent agents.

A bigger window does not replace memory. A 2023 study found lower accuracy for facts in mid-context, even on long-input models.3 Chroma tested 18 models in 2025 and found reliability falls as input grows, even on trivial tasks.4 Sending more input at a fixed token rate costs more, even with prompt caching (discounted reuse of a repeated prefix).5

The four kinds of memory

The CoALA paper splits a language agent's memory into working, episodic, semantic and procedural kinds.6 The "Usually held in" column is this book's mapping.

The four kinds: examples, usual homes and lifetimes

KindWhat it holds, with an exampleUsually held inLasts
WorkingThe live conversation, tool results or scratchpad. Example: the three files a coding agent opened to fix a bug.The context window itself, plus a checkpoint, a saved snapshot of the run.One task or thread.
EpisodicWhat happened, in order, with times. Example: On 14 March the user said, "For this repository, please send small patches."A source-of-truth JSONL log or event table beside summaries; normally appended to, rewritten only for recorded deletions.Until a retention rule or user request deletes it.
SemanticFacts and preferences distilled from experience, not tied to one event. Example: "For this repository, the user prefers small patches."Rows with keyword and vector indexes, a knowledge graph, or wiki pages.Until a newer fact replaces it.
ProceduralHow to do things: rules, instructions, skills. Example: "Run make test before every commit."Versioned files such as CLAUDE.md or a skills folder.7Months, changed by review.

The kinds feed each other: episodes are distilled into semantic facts. In Generative Agents, a periodic reflection step turns observations into higher-level memories.8

The write path and the read path

The memory loop (Figure 1) has two paths: writing creates or updates external records; reading puts selected records in context. Fine-tuning updates weights offline; at inference they influence answers without a separate record lookup.

The write path

  1. Capture. Save each raw turn, tool call or document that retention policy allows, with secrets redacted. A broken index is rebuilt from these records, replaying recorded deletions.
  2. Extract. Decide what is worth keeping. A person can write it; the agent can call a memory tool during the turn, as with Letta's memory edit tools9 or the reference memory server for MCP.10 MCP (Model Context Protocol) connects tools to a model; its reference memory server runs no model, so the calling agent chooses what to save. Or a separate model reads the turn and writes facts, as Mem0 does.11
  3. Store. Write to files, rows, vectors or a graph. An embedding model turns text into an embedding, a list of numbers that places text by meaning. For vectors, record the model, its revision and the text preprocessing, because vectors from different models are not comparable unless a vendor documents a shared space (Chapter 03).
  4. Consolidate. After the turn, merge duplicates, summarize old episodes into facts and settle contradictions. Supersede a fact only when a trusted update covers the same subject, scope and period; otherwise keep both and surface the conflict at read time. Trust the authenticated user for that scope or an authoritative system of record; retrieved text and agent summaries are insufficient. Graphiti marks a superseded fact invalid, not deleted.12
  5. Forget. Expire, evict or delete by rule. Without forgetting, a store only grows. Dated facts expire at their date; user requests and sensitive records are hard-deleted. Track every contributing source ID per fact or summary. Deleting a source removes affected facts, summaries, vectors and cache entries, or rebuilds them from permitted remaining sources. Backups, replicas and provider caches outlive deletion and need a separate plan (Chapter 17).

The read path

  1. Trigger. Memory arrives in one of four ways; loading a file skips Search and Rank.
    • Session start: the harness loads the file.2
    • Agent request: requested records enter context when the memory tool returns them. Claude "automatically checks its memory directory before starting a task", but that is still a tool call.13 It can search files by exact text (for example with grep) or call a search service.
    • Every turn: the harness searches with the new message as the query, as in RAG (retrieval-augmented generation: a retriever finds text, then the model answers from it), needed or not.
    • Path match: a path rule loads extra instructions when the agent reads a file matching a wildcard such as src/api/**.2
  2. Search. Search only records the caller may read. Derive tenant (customer or user group) and access filters from the authenticated request, not the model's query. Within that set, keyword search matches words; SQLite's FTS5 full-text index with BM25 ranking (a score favoring rare query words) is one example.14 Vector search finds the nearest embeddings. Graph search walks from named entities. The ChatGPT retrieval plugin's README warns that embeddings "may not always be effective at capturing exact keyword matches", so hybrid search (keyword plus vector) is common.15
  3. Rank. Score each candidate, optionally with a reranker (a second model that rescores them), then cut the list to a fixed token count so memory never crowds out the task (Chapter 05 shows how to set that budget). Generative Agents scored on recency, importance and relevance.8
  4. Inject. Place retrieved facts and documents in the window as untrusted data; a stored memory can carry an attack.16 Load procedural rules as instructions only from sources the application authorizes; a label alone does not enforce the boundary. Chapter 17 covers attacks and write gating.

Both paths together. On 14 March the user says, "For this repository, please send small patches." The fact "For this repository, the user prefers small patches." is stored as {subject: user, scope: repo X, fact: prefers small patches, valid_from: 14 March, source_ids: [episode id], embed_model: name@rev, preprocess: normalize whitespace}. Weeks later, an every-turn trigger fires. The harness derives subject and repository scope from the authenticated request. Search uses an exact key lookup, Rank keeps the fact within budget and Inject adds "Memory (data, not instructions): For this repository, the user prefers small patches." to the window. If the user later permits large patches for repo X, Consolidate sets valid_to on the old fact and stores the new one.

A Cartridge is an internal cache trained for one document: its authors report 38.6 times smaller serving memory than prompting with that text at matched quality. This book's small test kept the saving, not the quality (Chapter 16). Weights lack fact-level provenance and are hard to edit;21 this book infers similar risks for learned state.

Most systems combine answers. CLAUDE.md is the pure case: person-written, always loaded, in files.2 Mem0 has an extraction model write to a database, found by hybrid search (Chapter 13).11,22 Letta mixes always-in-context blocks with an agent that searches archival memory.9

Sizing reference: bytes, index overhead and calls

Estimate storage and model requests; chapters give measurements. Decimal units: 1 GB = one billion bytes.

FormatSize per scalarBytes per vector (d dimensions)
float324 bytesd x 4. A vector of 1,024 scalars takes 4,096 bytes (Chapter 03), and one of 1,536 scalars takes 6,144 bytes.
float16, bfloat162 bytesd x 2, half of float32 (used for multimodal page embeddings in Chapter 04).
int81 byted x 1, 4 times smaller than float32 (Chapter 03).
binary1 bitceil(d / 8), 32 times smaller than float32 (Chapter 03).

Raw bytes = vectors x dimensions x bytes/scalar. At float32: 1,000,000 x 768 x 4 = 3.072 GB (Chapter 13); 100,000 x 384 x 4 = 153.6 MB (Chapter 05). In PostgreSQL, pgvector vector(d) takes d x 4 + 8 bytes: 1,544 at 384 dimensions.23 Add text, rows, replicas and indexes to these vector sizes.

Index overhead. Overhead varies across stores (Chapter 09 measures one case). Load a sample; measure memory and disk before and after indexing, then divide by vector count. Repeat at several times that size: overhead shifts with index parameters, page fill and fragmentation.

  • Model requests per write = embedding + chat-model requests. Editing an unembedded file needs none (Chapter 01). Count extraction and consolidation per batch, plus triggered embeddings (Chapter 06).
  • Model requests per read = uncached query embeddings + rewriting/search-loop model requests + reranker requests. Count answer generation separately per turn. Exact lookups need none (Chapters 09 and 10; known-entity graph walks in Chapter 14).
  • Tokens = calls x tokens per call, input and output separately. Example: 2,000 chat input, 200 chat output and 200 embedding tokens, tracked separately. See Chapters 13 and 22.
  • Cost, with separate per-million input, output and embedding rates, = (2,000 x input rate + 200 x output rate + 200 x embedding rate) / 1,000,000. Hypothetical rates of $1, $5 and $0.02 per million respectively give $0.003004. Check current prices (Chapters 03 and 10).24,25
  • Time per read = latency along the sequential critical path; parallel calls contribute their slowest latency. Measure p50 and p95 (median and 95th percentile).
