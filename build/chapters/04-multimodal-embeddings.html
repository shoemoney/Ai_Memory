Multimodal embeddings

Shared vectors let a sentence find a picture across text, images, screenshots and video.

Maturity

Shipped

Best for

Agents that must find screenshots, photos, slides or video from a text description.

What it is

Multimodal models embed text, images, screenshots, video and sometimes audio in shared vectors (Chapter 03). Similar meanings sit close across forms.

Qwen3-VL-Embedding, released in January 2026, accepts "text, images, screenshots, and videos, as well as inputs containing a mixture of these modalities".1,2 Google's Gemini Embedding 2 maps "text, images, video, audio, and documents" into one space.3

Terms new in this chapter

Modality
An input type: text, image, video or audio.
Modality gap
Matching text and image vectors in separate regions.
Multi-vector
Many vectors per item (Chapter 03), here per page patch (small image tile). MaxSim sums query tokens’ best patch scores.
Backbone
Pretrained core. Adapters add weights, sometimes separately licensed.
Interleaved
Text and images mixed in one input.
nDCG@5
Normalized discounted cumulative gain at five: relevance versus the ideal top five; 0 to 100 here (Chapter 05).
bfloat16
Two-byte float with float32's exponent range and fewer precision bits. float16: same bytes, narrower range. Stored-vector precision is independent (Chapter 03).

How it works

On write, embed items and save vectors and paths. On read, embed the question, search, optionally rerank and pass matching originals to the model.

One vector or many per page

Single-vector models compress pages into one vector; ColPali and ColQwen2 keep one vector per patch. The ColPali authors call this "ColBERT-style multi-vector representations" and introduced ViDoRe (visual document retrieval) to argue that embedding page images beats indexing text from optical character recognition (OCR), which can lose the link between a chart label and its bar.8,9 Storage is the cost. ColQwen2 caps a page at 768 visual patches8 of 128 numbers each, plus a few special text-token vectors; its card shows an example page with 755 vectors.8 The table sizes one million pages in float16 (two bytes per number).

At 768 vectors per page, illustrative multi-vector storage is 24 times the 8B single vector and 48 times the 2B one. The 2B model truncates anywhere from 64 to 2048 numbers; no source reports quality at 512.1 Qdrant supports multi-vector MaxSim scoring since v1.10.0;21 Chapter 11 gives the recipe.

The reranker that pairs with it

Reranking adds one model pass per query/candidate pair. Qwen3-VL-Reranker (2B and 8B) takes mixed text and image pairs.4 Re-score a few dozen candidates on GPU; on CPU, skip reranking or cap it at three to five (about 13 seconds per screenshot pair below). ViDoRe V3 reports gains from text rerankers;22 only vendor tables measure visual reranking,4 so require better top-five hits on your queries (Chapter 05).

One backbone, and the modality gap

CLIP-style models train separate text and image encoders to place matching captions and images near each other; Qwen3-VL-Embedding uses one backbone.4 Whether the gap in two-encoder models20 also appears in this model is unmeasured. A gap could favor captions over matching screenshots. Test whether the top five change before mixing them in one index.

The alternative: caption first

Caption on write for editable text embeddings (Chapter 03), adding a generation call. Retrieval sees only captioned details.

Separate caption collections use their own embedder. Merge ranks (Chapter 05); scores across embedding spaces are incomparable.

The 50-query test

  1. Test five layouts on identical items: images only (multimodal embedder), captions only (text embedder), rank fusion over those separate collections, one mixed index using the multimodal embedder for images, captions and queries deduplicated by item id, and one vector encoding image plus caption jointly.
  2. Write 50 requests before seeing captions. Record target ids for exact lookup; for descriptive search, pool candidates and judge relevance blind to route.
  3. Fetch five distinct item ids per route; count requests with targets or relevant items among them.
  4. Report paired wins/losses. Prefer simplicity unless the alternative answers about five more of the same 50 requests correctly within the top five. This deployment margin is not a significance test.

Good for and not for

Good for

  • Search boxes where people describe an image, a slide or a moment in words.
  • Content whose meaning is visual: screenshots, charts, slides, photos with no useful text.
  • A picture plus a line describing it, stored as one vector; if the text is unrelated, embed the image alone (Use case 2).
  • Local-first: Qwen3-VL-Embedding-2B has open weights; about 4 GB in bfloat16 (2B parameters x 2 bytes; computed, not measured).1
  • Documents where OCR loses the layout: on ViDoRe V3's tested datasets, visual retrievers beat its textual baselines.22

Not for

  • A text-first collection: a text embedder scores higher on text (Chapter 03).1
  • Millions of pages without a multi-vector budget: 196.6 GB per million pages in float16.
  • Speech inside video: Gemini Embedding 2 ignores the audio track, so send it separately (see Gotchas).3
  • Tracking where objects are over time: an image embedding finds a matching view, not a position. Extract positions into structured records for spatial tracking.

Use cases

1Screenshot memory for a computer-use agent

Situation
A computer-use agent seeks a failed-deploy screen outside its context window.
Why it fits
Qwen3-VL-Embedding retrieves screenshots. Save timestamps, tasks and last actions with images; retrieve past states by text intent instead of replaying history.1 Neither the model card nor the paper tests agent screenshot tasks.
Pair with
Task/window filters and reranking. Re-observe before acting: retrieved screens show past state.

2A social feed where each post is a picture and one line

Situation
An assistant searches a million posts for "dog on a beach at sunset", but the post text is an unrelated joke.
Why it fits
Qwen3-VL-Embedding can fuse text and image into one vector, but the joke would pull it away from "dog on a beach". Embed the image alone, and add the fused vector only if the 50-query test shows a clear gain over image-only.1
Pair with
A separate text embedding of the line for text-only queries, merged as in Chapter 05.

3Slide and PDF search without OCR

Situation
An LLM answers from thousands of slide decks, but OCR scrambles chart labels and text retrieval misses pages.
Why it fits
ColQwen2 embeds page images. ViDoRe V3 reports stronger visual retrieval on its tested datasets.22 At 768 vectors, a 200-page deck needs about 39 MB before indexing.
Pair with
A reranker. For slow scoring, shortlist before MaxSim with one Qwen3-VL-Embedding vector per page. For limited storage, keep only those vectors and rerank originals with Qwen3-VL-Reranker-2B; measure latency.

4A laptop archive that stays offline

Situation
An offline laptop assistant searches 10,000 field photos and voice notes.
Why it fits
EmbeddingGemma 2 supports all these inputs locally. The 440M parameters (text and images) or 740M (all modalities) take about 0.88 GB or 1.48 GB of bfloat16 weights before runtime memory, or about 1.76 GB or 2.96 GB in float32. Computed from the card; EmbeddingGemma 2 was not run.11
Pair with
Local files and SQLite (Chapter 12), a 768-number vector per item, and date/project filters. Test recall on real photos and speech before choosing a smaller vector.

5Finding a moment in a video

Situation
Search hour-long screen recordings for "the part where the error dialog appears".
Why it fits
Gemini Embedding 2 samples at most 32 frames per video.3 Size clips, up to 120 seconds, for the shortest event to catch; shorter clips give denser sampling. Sampling all 32 frames averages one per 3.75 seconds for 120-second clips (30 clips an hour), one per second for 32-second clips (about 113 clips an hour). Neither guarantees catching brief dialogs. Store start times.
Pair with
The audio track, embedded as audio on its own (see Gotchas).3

Own measurement

Tested here: ViDoRe V3 subset (318 English queries, 1,110 pages), not MMEB-V2 or ViDoRe V2, not comparable with vendor figures, including Nomic Embed Multimodal 7B's 58.8. nDCG@5 was 58.77 (95% bootstrap interval over queries, 55.39 to 62.20) for Qwen3-VL-Embedding-8B and 55.17 (51.64 to 58.74) for Nomic Embed Multimodal 7B. Both used 4-bit weights (compressed; Chapter 06), which may lower scores. Paired difference: 3.60 points (95% paired bootstrap interval 1.00 to 6.19, 10,000 resamples of shared query ids), so Qwen3-VL-Embedding-8B scored higher here. A separate bfloat16 2B run scored 54.98 (51.36 to 58.55) on this subset; runtime and precision differ. Companion: benchmarks/mteb-large/vidore.py; the folder also holds text-embedding runs.

Scope and scale

Keep paths current; replace or delete vectors with originals, and re-embed the collection when changing models. The answer model sees selected images or clips; its resolution and frame policy set token costs.4

  • Per write: one embedding pass per item, no generation call. Per read: one query embedding plus one pair-scoring pass per reranked candidate (Chapter 00).
  • Storage: raw float16 sizes follow the table above (method in Chapter 00). Qwen3-VL-Embedding-2B in float16 needs 4.1 GB for 100 users at 10,000 memories each, before originals, payloads and indexes.
  • Memory: budget about 4 GB of bfloat16 weights per independently loaded Qwen3-VL-Embedding-2B. For shared instances, measure peak memory at intended concurrency.

Benchmark real page sizes and concurrency; full-page GPU memory and latency are unmeasured. Use captions if visuals add little (Chapter 03), fewer reranking candidates for latency (Chapter 05), or a dedicated vector store for index RAM (Chapter 11). No source gives an item-count cutoff.

Setup walkthrough

Create three PNGs, embed them and a query, store vectors in Qdrant, filter, rerank and return the original filename. Start a child Bash shell; paste shell blocks in order (or source setup.sh) to preserve directories and exports. Failed commands stop it.   4. Write, then read in a fresh process

    write.py stores three generated images' vectors and paths. search.py embeds a query in a fresh process, searches Qdrant, reranks originals, checks the filename and retains the collection. Without avx512_bf16 or amx_bf16 in lscpu, replace torch.bfloat16 with torch.float32 in write.py, search.py and warm.py; weight memory doubles. decoy.png duplicates circle.png in another album: an unfiltered search returns it; the filter excludes it.

    pythonwrite.pyTested
    from pathlib import Path
import time
import torch
from PIL import Image, ImageDraw
from qdrant_client import QdrantClient, models as m
from src.models.qwen3_vl_embedding import Qwen3VLEmbedder

torch.set_num_threads(8)
model = Qwen3VLEmbedder('models/Qwen3-VL-Embedding-2B',
    torch_dtype=torch.bfloat16, attn_implementation='sdpa',
    max_length=512, max_pixels=224 * 224)
paths = []
for name, color, shape in [('circle', 'red', 'ellipse'),
                           ('square', 'blue', 'rectangle'),
                           ('decoy', 'red', 'ellipse')]:
    image = Image.new('RGB', (224, 224), 'white')
    getattr(ImageDraw.Draw(image), shape)((32, 32, 192, 192), fill=color)
    path = str(Path(name + '.png').resolve())
    image.save(path)
    paths.append(path)
started = time.perf_counter()
vectors = torch.cat([model.process([{'image': p}]) for p in paths])
print(f'image embedding: {time.perf_counter() - started:.3f} s')
client = QdrantClient(url='http://127.0.0.1:39040')
client.create_collection('pictures', vectors_config=m.VectorParams(
    size=2048, distance=m.Distance.COSINE))

Gotchas

Gotcha: pgvector index limits

pgvector indexes up to 2,000 numbers per vector, or 4,000 with its two-byte halfvec type (Chapter 08). Use halfvec for 2048 or 3072; truncate 4096.

Gotcha: Gemini Embedding 2 media and page caps

For frame density and clip length, see Use case 5. In Gemini Embedding 2, "Audio tracks are not processed in video files".3 A 40-page deck must be split at 6 pages per request.3

Gotcha: hosted availability varies

Alibaba Model Studio Qwen models are region-bound with separate keys.19 Pinecone (November 2026) says Gemini Embedding 2 "is only offered as a text model today" in its integration, though its native API takes images.25 Check the surface you call.

Gotcha: EmbeddingGemma 2 precision

Run EmbeddingGemma 2 in bfloat16 where supported and float32 otherwise (Chapter 03); the card warns that float16 can produce NaNs.11 Check finite vectors and known query/item pairs before indexing.

Verdict

Verdict: one small model, then measure

Pick it when remembered content is visual: screenshots, photos, slides, short video. Start with Qwen3-VL-Embedding-2B. The walkthrough checks plumbing. For latency decisions, time identical queries, candidates and caps end to end in fresh and resident processes. The ViDoRe V3 subset scored 54.98 for 2B versus 58.77 for 8B; precision and runtime differed. Run the 50-query test. Choose CPU, GPU or hosted against a preset latency/cost budget using warm real screenshots; include hosted network time and reranking. Use a page model such as ColQwen2 for slides and scans. If weights exceed local memory, consider hosted inference (Gemini Embedding 2 for audio or PDF) only if the originals may leave the device. Offline, test EmbeddingGemma 2 (card claims; not run here).1,8,11,24

Use captions and a text embedder (Chapter 03) for word-focused queries or when captions keep needed details. For audits, retain originals and provenance; captions are inspection aids, not proof. If patch vectors exceed budget, try one visual vector per page with reranking (Use case 3). Store vectors in pgvector (see Gotchas and Chapter 08) or a dedicated vector store (Chapter 11), and merge text results (Chapter 05). Worked example: Chapter 23; page multi-vectors: Chapter 11.
