What it is

Knowledge-graph memory stores nodes (people or companies) and edges (their relationships), extracted by a model or written directly.

Follow entity links to answer "Who knows the person who introduced me to Bluefin?", or read community summaries. Microsoft's GraphRAG paper finds vector retrieval strong for local questions, weak for corpus-wide themes.1 Some systems also track time. Graphiti, the open-source engine behind Zep, says: "facts have validity windows. When information changes, old facts are invalidated, not deleted".2

Terms new in this chapter

Cypher
Neo4j’s language for matching node and edge patterns.
Valid time
When a claim applies in the world; in this walkthrough, the half-open interval from valid_from to invalid_at.
Recorded time
When a version was live in the store; in this walkthrough, from recorded_at to superseded_at. Also called transaction time.
Community summary
Model-written text describing a cluster of closely linked entities.
Episode
A message, note or record Graphiti ingests and retains as extracted facts' source.
Multi-hop question
A question whose answer needs two or more edges in a row.

How it works

Extract: a model emits entities and relationships from text. Resolve entities: match mentions to existing people or firms. Reconcile facts: close earlier relationships only when evidence and validity rules warrant it. Store: save nodes and edges. Retrieve: use a path query for exact relationship patterns. GraphRAG local search gathers context around relevant entities; global search reads community summaries,1 while HippoRAG 2 ranks passages with personalized PageRank (which spreads query relevance across linked nodes to score passages).

Extraction requires generation calls; queries depend on their output. If three edges are each 90% likely to be correct and errors are independent, all three are correct about 73% of the time. This is not answer accuracy. Graphiti's default fact search makes no generative LLM call.3

Two timelines

Each fact can carry a valid time and a recorded time; Graphiti describes tracking both.2 The walkthrough implements both directly in Cypher, without Graphiti.

EventValid fromRecorded at
Alice works at Acme.2024-03-012024-03-02
The application learns she joined Bluefin.2026-09-012026-09-07
A correction moves the Bluefin start date earlier.2026-08-152026-11-15

Updates close recorded intervals and append complete replacements. For 20 August 2026, current knowledge returns Bluefin; knowledge recorded on 1 November 2026 returns Acme, before the correction. Assume one employer at a time; intervals include their start, exclude their end.

Good for and not for

Good for

  • Multi-hop connections between people, companies and projects.
  • Changing relationships needing joins, history and sources. Structured updates can write edges directly; a lone attribute needs SQL.
  • Whole-corpus questions such as "what themes recur across these reports", which top-k vector search answers poorly.
  • Known entity types. Graphiti accepts Pydantic types (Python classes defining and validating fields).2
  • Teams able to afford extraction and inspect edges.

Not for

  • Single-passage lookups such as "what did I say about X on Tuesday". Use vectors (Chapter 03) or files (Chapter 01).
  • A few dozen notes. Read the files.
  • Preferences and short facts about one user need a keyed profile. For a few relations, the MCP reference memory server is the lightest graph option.
  • Local models that cannot reliably return structured output. Test one first.2
  • Write volumes that outrun extraction. If passage lookup suffices, use timestamped vectors.

Use cases

1Who knows whom in a personal network

Situation
After recording investor meetings and introductions, a founder asks "Who knows the person who introduced me to Bluefin?" Keyword search cannot join notes.
Why it fits
Typed edges join people and firms: Bluefin, its introducer, then their contacts. HippoRAG 2 reports gains on associative recall (answers needing linked facts), also found in a reduced local run (Numbers).7
Pair with
Neo4j for the tested setup, or embedded FalkorDBLite without a server. Keep source notes for quotations.

2Changing facts that link several entities

Situation
Over a year, an assistant hears "I moved" and "I switched to Bluefin". Plain notes may preserve stale answers.
Why it fits
Each fact has a start and end date, and a change closes the old edge instead of deleting it.2 The example answers Acme or Bluefin by recorded date. One job or address needs SQL validity columns (Verdict); use graphs when facts join people and firms.
Pair with
Graphiti, or the hand-written pattern in the walkthrough. Store the source episode on every edge.

3One question over thousands of reports

Situation
An analyst asks which causes recur across thousands of incident reports. Top-k vector search returns ten reports, missing the pattern.
Why it fits
GraphRAG global search answers from community summaries built over the whole corpus.1 Microsoft reports that LazyGraphRAG avoids most up-front indexing cost,5 but LazyGraphRAG was not run locally; try RAPTOR summaries (Chapter 05) first.
Pair with
A corpus slice first, since indexing is expensive.4

4Multi-hop research across documents

Situation
A team asks which component supplier a named company owns. A bridging entity joins two documents.
Why it fits
HippoRAG 2 ranks passages over its extracted graph with personalized PageRank.7 LightRAG retrieves at a local and a global level over its graph.6
Pair with
A reranker, hybrid search (Chapter 05), and sampled edge checks.

5A small graph for one developer, no database

Situation
A developer wants Claude Desktop or Claude Code to retain people, projects and relations across sessions without a database.
Why it fits
The MCP reference memory server keeps entities, relations and observations in one local file and exposes nine tools. The client model chooses writes; the server makes no model call.12
Pair with
The file under git. Use filtered reads if only the response is too large. Measure p95 write latency at your note rate. Migrate when it exceeds your latency budget, writers regularly wait on the lock, or queries need dated relationships.

Neither LazyGraphRAG's 0.1% cost (Microsoft's report; cited release points to Azure integrations; not run locally) nor HippoRAG 2's +7% average across datasets was reproduced as published. A reduced run (150 2Wiki questions; Qwen2.5-3B-Instruct, replacing the paper's 70B) scored answer F1 (reference-answer token overlap, out of 100) of 46.3 for HippoRAG 2 versus dense retrieval's 32.5: a 13.8-point gain (95% interval 6.6 to 21.2). Supporting-passage recall at five was 78.5% versus 53.8%. That supports the direction on one dataset, not the 7% average. See benchmarks/paper-reruns.

Zep and Mem0 dispute scores; an independent audit and the benchmark repository's issue thread both contest the LoCoMo answer key.28,31 Evaluate on your own data.

Tested on 22 November 2026 (Qwen2.5-14B-Instruct Q4_K_M, 4-bit quantized; CPU MiniLM embeddings; three local judge votes per answer, majority wins; 96 GB Apple Silicon), Graphiti scored 44/123 on completed LoCoMo questions from conversations 0 through 3 (35.8%, 95% interval 27.9 to 44.6) against full context's 71/123 (57.7%, 95% interval 48.9 to 66.1). Of 320 targeted questions each, full context completed 320 (180 correct), Graphiti 123 (44), Cognee 67 (39). Retries and the deadline limited completion. Pairing requires answers and three votes from every method: 67 questions from conversations 0, 1 and 3. Graphiti scored 22/67 (32.8%, 95% Wilson interval 22.8 to 44.7); Cognee and full context each scored 39/67 (58.2%, 95% interval 46.3 to 69.3). Scores are conditional on completion.

Ingestion per conversation took Graphiti 37.6 to 148.8 minutes against vector-only Mem0 OSS's 25.8 to 39.6, including retries and waits on a shared model host, so these are observations, not controlled throughput.

On 150 LongMemEval items, a 3B local reader scored 66.7% with full context and 61.3% with dense retrieval, no clear gap. Only these two baselines ran, without graphs, Zep or MemGPT. Chapter 17 has the LoCoMo table; the harness is in the companion repository under benchmarks/locomo.

Scope and scale

Calls per operation:2,23

  • Direct edge write or lookup: zero generation or embedding calls.
  • Graphiti episode ingestion: several generation calls plus embeddings. Retries and entity matching vary the count.
  • Default Graphiti fact search: one query embedding call; add one generation call only if you turn the facts into a prose answer.

The extractor queue fills first. At the walkthrough's 57 to 115 seconds per episode on CPU with one slot, 60 writes take roughly one to two hours. Its 171.7-second timer covers index setup, two writes, checks, search and model loading, excluding installation and downloads. Time a warmed batch at your concurrency. Graphiti's default of 10 concurrent operations can exceed a local model's capacity.2

Storage estimate: at 768 dimensions in float32 (per-vector size in the Chapter 00 sizing reference), one million embedded entities plus one million embedded facts take about 6.14 GB for vectors alone, before episodes, properties and indexes. Partition users with Graphiti's group_id; measure recall and ingestion backlog as memory grows. If backlog exceeds your freshness budget, batch extraction or use Chapter 20’s synchronous SQL assistant when its narrower design fits.

  2. Write both timelines, then query them

    Save this whole file (initial write, September update, November correction) as plain Cypher and run it once in the empty lab; cypher-shell reads standard input.25 The queries use latest knowledge, then fixed valid and recorded dates. Sources name version updates, not all evidence: Acme starts per note-1 and ends per correction-3.

    Fixture-specific updates use a stable person ID and atomically close and append versions. November selects September-recorded Acme/Bluefin versions; reusable updates need date parameters and interval selection. The final query follows KNOWS and INTRODUCED to find the introducer's contacts.

  4. Initialize, ingest and search

    Save graph.py. Ingestion alone builds indexes and adds two dated notes. Both processes check episodes, direction, invalidation, activity and recall. Exact-English old-edge matching can reject or miss paraphrases. Clients use IPv4 loopback and a separate schema. SEMAPHORE_LIMIT=1 matches Ollama's single request. Reciprocal rank fusion (Chapter 05) combines semantic and keyword ranks. Search uses rank fusion. Supplying a local Ollama reranker client prevents Graphiti from initializing its OpenAI default; no reranking runs.3 Raw search needs filtering: at 22 November, keep edges starting by then with no end or a later end. Keep positive Bluefin, exclude obsolete positive Acme; negative Acme asserts no employer. The script neither filters validity nor checks paraphrased live employers.

Gotchas

Gotcha: one wrong edge poisons later answers

Merging two people named Smith combines their edges and contaminates later reads. Keep the source episode on each edge, as Graphiti does,2 and inspect retrieved edges. For direct writes, key nodes by a stable, user-scoped contact ID. Graphiti model resolution is not tested by this fixture. Proposed test: ingest two Smiths with different contact IDs and employers; each ID must retrieve only its own employment edge.

Gotcha: relation names drift without a schema

Free-form extraction can write works_at, employed_by and job for one fact. Graphiti lets you prescribe entity and edge types as Pydantic models;2 Mem0's Platform-only graph leaves relationships untyped.8 Constrain edge types first.

Gotcha: passing ingestion is not accuracy

A smoke-test pass measures no accuracy. Test real episodes, contradictions and empty cases against expected facts. Qwen2.5-7B-Instruct passed on CPU and an 8 GB consumer GPU. Qwen3-0.6B (qwen3:0.6b) passed CPU ingestion and search in 83.2 seconds under the printed 600-second budget; a fresh read also passed. Its earlier 300-second trial timed out and returned no facts; the cause remains unknown. Extraction needs no GPU; Ollama supports CPU execution.27 Graphiti's README warns that smaller models can give wrong schemas and failed ingestion.2

Gotcha: Graphiti's bundled servers are open by default

Graphiti's bundled MCP server and REST service have no authentication or prompt-injection filter; keep them off untrusted networks.2 See Chapter 17.

Verdict

Verdict: earn the graph

Choose a graph only when all three hold: questions need multi-hop joins or corpus-wide answers beyond files and vectors; typed writes or accurate extraction are affordable; someone reviews sampled edges. Delete or correct an episode, then confirm derived edges, embeddings and summaries no longer present its old fact as current. Otherwise, treat propagation as unsupported.

One job or address needs validity and recorded-version columns in Postgres or SQLite (Chapters 08 and 12; hybrid facts and edges in Chapter 23). Start with files (Chapter 01), timestamped vectors (Chapter 03) or RAPTOR summaries (Chapter 05). Try AGE for Postgres graph queries, or GraphRAG global search on a corpus slice.
