How to read this book

Build memory that an agent based on a large language model (LLM) can read and update. Entry points: Chapter 00 for the memory loop, 01 for flat files, 17 to evaluate, secure and operate memory, 18 to compare architectures, 20 for one assistant's six stages.

Three kinds of chapter

Architecture chapters, 01–14. Each has a summary, a strip showing maturity, setup effort and running cost, and nine sections: What it is, How it works, Good for and not for, Use cases, Numbers, Setup walkthrough, Gotchas, Verdict and Sources.

Essay chapters, 00 and 15–19. They cover memory basics, history, research, security, evaluation and operations, architecture selection and a field report. Each keeps the summary and Sources list. Strip fields vary by topic; setup and cost ratings are omitted. Read these chapters in any order.

Case studies, 20–23. These designs use only self-hosted models: one assistant in six memory stages, then a painter, a doctor's office and an international homebuilder. The last three have a full-page "What does what" map. These reference designs offer no legal, compliance, tax or clinical advice.

Running the Setup walkthroughs

Use disposable service instances, such as temporary databases without real data. Most walkthroughs refuse an existing working folder, mark created items with a run token (random string) and clean up only matching items. Some short walkthroughs use fixed names; keep those disposable too.

For a named file longer than eight lines, the chapter prints a one-line pointer that links to it. In the PDF edition, files are attached (Attachments panel, a paperclip icon) and are in the companion repository, whose address Appendix B prints. with its repository path; this appendix prints the repository address. Labels such as ch09-code05 mean Chapter 09, fifth named file; the repository README maps labels to files. Source links appear under sources/ in the repository.

Editorial ratings

Setup effort (colored dots): 1 is edit files on one machine; 3 is one database or service to run; 5 is several services plus model hosting.
Running cost (dark dots): count only what memory adds over the same agent without it. 1 adds no service or hardware, though compute/storage charges may grow; 3 is one managed service or small virtual machine; 5 is several paid managed services or an added accelerator.

Ratings are editorial judgments, not measurements or budgets; cost dots compare added infrastructure. Even numbers fall between anchors. Architecture strips and Chapter 18 share these dots; essay strips omit them. Resolve ties using existing infrastructure, hosting limits and Chapter 18.
