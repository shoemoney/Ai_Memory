Memory frameworks

A memory framework decides how an agent saves facts, retrieves them and places them in a language model’s context.

What it is

Memory frameworks save and retrieve facts. Choose by who selects them, a model or your code, and the saving cost.

The Model Context Protocol (MCP) exposes tools; its memory server stores local entities/notes. LangGraph resumes conversations (threads) from state snapshots (checkpoints); Store shares facts across threads. Letta V1 is retired; Letta Code is current. Use LangGraph Store for keyed facts: namespace identifies whose, key identifies which. For extraction, try Mem0 (Chapter 06) or Hindsight (Step 6).1,2,3

How it works

Direct writes need no model. Extraction/agent edits add calls (Step 7); semantic indexing embeds writes/queries. Letta V1 blocks stay in prompts; keyed/semantic reads fetch on demand.1,2,5

Mem0: current retrieval design

Mem0’s April 2026 algorithm v3 (package mem0ai 2.2.1; algorithm versions are separate) makes one generative call per extraction-enabled save. ADD-only facts lack stable field keys. Your code must search user-scoped memories, identify contradictions and delete superseded IDs (Gotchas; Chapter 06’s delete call). It links entities; retrieval adds BM25 keyword scores, entity signals and time-aware ranking to semantic search. Python’s [nlp] extra and spaCy model enable entity extraction and keyword lemmatization, and Qdrant BM25 also needs fastembed. Chapter 06’s minimal installation uses semantic search only.5,6

In mem0ai==2.2.1, keyword and entity signals only re-rank semantic hits, so they cannot recover an exact match it missed. If exact identifiers matter, measure how often semantic search finds them and add a keyword branch.6

Mem0 OSS is self-run. Mem0 Platform’s proprietary optimizations, terms and published scores do not carry over (Benchmark evidence).5,7

Good for and not for

Good for

  • Notes the agent writes that must survive a session.
  • Namespaced facts shared across agent threads.
  • Preferences picked out for a small prompt budget.
  • Agent-editable context with an audit trail.

Not for

  • Fixed profile fields, which belong in a database (Chapter 08).
  • Short project instructions, which belong in a file (Chapter 01).
  • Authoritative task ownership, which needs transactional guarantees (Chapter 08).
  • Exact evidence, where you should also keep the original sources.
  • Histories that fit in context, or where plain retrieval meets your target; local extraction did not beat full context (Chapter 17).

Adoption checks for seven tools (Chapter 01 covers repository-memory upkeep):

  • Claude-Mem and AgentMemory. Both require supported capture hooks; audit capture/export/deletion separately from hook removal.22,23
  • Honcho. Workspace/session/peer scopes track knowledge of others. Keep direct evidence, label inferences, budget background reasoning. Before sharing beliefs, inspect Dream Histories (inference logs), correct sources, test scoped deletion.18,30
  • memU. Chat-model calls outside storage convert history into candidate skills; budget/log separately. Separate human instructions, candidates and reviewed skills. Test, approve and version before reuse; revoke after regression failures (Chapter 17).16
  • MemPalace and EverOS. For exact quotations, try MemPalace’s verbatim retrieval before extraction. Recall@5 (correct item among five retrieved) measures retrieval, not answer accuracy. EverOS derives indexes/reflected memories from Markdown; its answer scores cannot compare with retrieval-only Recall@5. Export both source corpora; verify deletion across sources, derived stores, exports and backups. EverOS deletes by session/user/agent; deleting one session leaves aggregates.25,26
  • Strands with MongoDB. SnapshotSessionManager resumes sessions; MemoryManager searches long-term memory within a scope, and time to live (TTL) limits how long items survive before expiry. Choose scope from authenticated application state. Closing the agent context flushes pending extraction before closing connections.27

Numbers

Scope and scale

Server 2.2.1 reads the entire file per read. Writes lock, read, modify and atomically replace it; other processes wait. Stale locks recover, but sharing requires exclusive file creation. File size increases work and lock wait: set MEMORY_MAX_FILE_BYTES, MEMORY_MAX_ENTITIES and MEMORY_MAX_RELATIONS. They are unset by default.42

The MCP, keyed LangGraph Store and Letta V1 fixtures issue storage calls directly and use no inference tokens; their cost is process, API and disk work, with no latency promised. The Letta Code fixture also pays for the model turn that selects and issues each edit (Step 7 reports the times).1,2,4,5

These are arithmetic budgets, not measured defaults; see Chapter 00’s sizing reference.

Benchmark evidence

Mem0’s managed April 2026 stack claims LoCoMo 92.5 and LongMemEval 94.4 with top-200 retrieval: percent correct on long-conversation questions (Chapter 17). These vendor claims are untested here. Locally, benchmarks/longmemeval-frameworks in the companion repository tested Mem0 OSS and Graphiti with 3B extraction on LongMemEval. Ingestion per history took Mem0 19 to 58 minutes; Graphiti took two to five hours and about five times the tokens. Within the shared 14-hour wall-clock budget (Chapter 17), three histories finished, one question each; both frameworks scored zero. That cannot rank them or test vendor figures. The vendor harness defaults to GPT-4o for answering and judging; its OSS comparison uses GPT-5 for both. Record retrieval depth, extractor, answerer and judge before comparing scores.5,7

Tested locally with a 14B model (harness: benchmarks/locomo in the companion repository), Mem0 OSS scored 66/123 on LoCoMo (53.7%), between plain RAG (62/123) and full context (71/123). With extraction off (harness: benchmarks/longmemeval), it earned the same aggregate score as dense retrieval on LongMemEval: 165/300 (55.0%). from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.store.sqlite import SqliteStore

class State(TypedDict):
    answer: str

def recall(state, *, store):
    item = store.get(('users', 'test-user'), 'drink')
    return {'answer': item.value['text'] if item else 'missing'}

root = Path('/var/tmp/memlab-13/run')
with SqliteStore.from_conn_string(str(root / 'store.db')) as store:
    with SqliteSaver.from_conn_string(str(root / 'checkpoints.db')) as saver:
        store.setup()
        builder = StateGraph(State)
        builder.add_node('recall', recall)
        builder.add_edge(START, 'recall')
        builder.add_edge('recall', END)
        graph = builder.compile(store=store, checkpointer=saver)

import sqlite3
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.store.sqlite import SqliteStore

class State(TypedDict):
    draft: str
    action_key: str

# A durable fake external service, outside the checkpoint database.
with sqlite3.connect('external.db') as external:
    external.execute('CREATE TABLE IF NOT EXISTS sent (key TEXT PRIMARY KEY)')
    def send_once(key):
        external.execute('INSERT OR IGNORE INTO sent VALUES (?)', (key,))
        external.commit()

    def prepare(state):
        send_once(state['action_key'])
        return {'draft': state['draft']}

    with SqliteStore.from_conn_string('fork-store.db') as store:
        with SqliteSaver.from_conn_string('fork-checkpoints.db') as saver:
            store.setup()
            builder = StateGraph(State)
            builder.add_node('prepare', prepare)
            builder.add_edge(START, 'prepare')
            builder.add_edge('prepare', END)
            g = builder.compile(store=store, checkpointer=saver,
                          interrupt_before=['prepare'])
            cfg = {'configurable': {'thread_id': 'plan'}}
            g.invoke({'draft': '', 'action_key': 'send:plan-7:v1'}, cfg)
            root = g.get_state(cfg).config
            blue = g.update_state(root, {'draft': 'Use blue paint'})
            green = g.update_state(root, {'draft': 'Use green paint'})
            assert g.get_state(blue).values['draft'] == 'Use blue paint'
            assert g.get_state(green).values['draft'] == 'Use green paint'
            ns = ('approved', 'project-7')
            assert store.get(ns, 'paint') is None
            print('two isolated drafts; shared Store empty')
            approved = g.invoke(None, blue)  # Human chooses blue.
            store.put(ns, 'paint', {'text': approved['draft']})
            g.invoke(None, green)  # Replays the same logical external action.
            assert external.execute('SELECT count(*) FROM sent').fetchone()[0] == 1
            print('repeated action key: one simulated send')
            rewound = g.invoke(None, root)
            assert rewound['draft'] == ''
            assert store.get(ns, 'paint').value['text'] == 'Use blue paint'
            print('rewind: draft empty; approved Store fact still blue')
            store.delete(ns, 'paint')
            saver.delete_thread('plan')
            external.execute('DELETE FROM sent')
            external.commit()
            assert store.get(ns, 'paint') is None
            print('cleanup OK')

Gotchas

Gotcha: ADD-only stores keep contradicted facts

Mem0 keeps both “I prefer coffee” and later “I now prefer tea.” This correction test was not run here. Do not adopt Mem0 OSS for authoritative corrections until it passes. Check:

  1. The tea fact is stored.
  2. The fresh thread’s prompt identifies tea as current; coffee is absent or explicitly historical.
  3. A fresh thread answers tea.

Record the first failure. Ranking may miss current facts. Resolve per user, field and effective time; test late-arriving history. Before deletion, fetch the user’s facts for that field and confirm contradiction. Age-based deletion also loses valid old facts, such as allergies.5

Gotcha: Retrieved text is untrusted

Trusted application code chooses tenant scope, never a model-generated user id. Observations/learned skills are data, not instructions. Chapter 17 tests injection/isolation.

Gotcha: Checkpoints can retain deleted facts

Store deletion leaves earlier thread state, cached prompts, exports and backups. Test every readable copy.2
