What it is

Redis is a fast shared notepad for agents: a server that keeps data in RAM in ready-made structures (hashes, lists, streams, sorted sets), with keys that can expire. Valkey is a community fork with the same protocol.

Agents use it for sessions, recent messages and facts, cached answers and worker coordination. Disk writes are optional (snapshots or a log), so a crash can lose recent writes.1

Redis is a hot tier in front of a durable store: Chapter 08’s database stays the record and rebuilds Redis when needed. Chapter 10 covers caching.

Terms new in this chapter

TTL
A key's lifetime, set with EXPIRE.
Hit, miss, eviction
A hit returns a cached result; a miss finds none. Eviction drops keys at the memory limit.
RDB snapshot
A copy of the whole dataset written to disk on a schedule such as save 60 1000 (seconds, then changed keys).1
AOF
Append-only file. A log of every write, flushed to disk under one of three policies: always (each write batch), everysec or no (when the OS decides).1
Stream
An append-only log of entries with ids, read by position or by a group of workers.
Consumer group
A stream feature that hands each entry to one worker in the group and tracks whether it was acknowledged.

HNSW is defined in the Chapter 00 terms box and compared with other index families in Chapter 11. KNN, FLAT and quantization are in the glossary appendix.

How it works

The app names keys such as session:alice; the key's type sets its commands. HGET reads the summary in one round trip; pipeline it with XREVRANGE to fetch history in that round trip too. Redis stores and compares embeddings from your model (Chapter 03) and makes no model call.

EXPIRE sets a TTL on a whole key of any type and removes the key when it fires. Stream and sorted-set entries stay until your code trims them, and Vector Set elements until VREM or key expiry.

Two vector options

Redis 8 has two ways to search by meaning. The Query Engine (formerly the RediSearch module, now in Redis 8) indexes hashes or JSON documents. A vector field can be FLAT, HNSW or (from Redis 8.2) SVS-VAMANA (a graph index with vector compression), in float32 or a narrower type; the figures here are float32 HNSW. One query can filter on tag, numeric and text fields.2 Vector Sets are a separate data type: VADD adds an element, VREM removes it and VSIM searches. With persistence on, the graph is stored in the snapshot and reloaded at restart, so vectors need no re-insert. Recent-write survival depends on the persistence policy and crash type (see the restart test). Docs claim, not tested here.3

Note: two score scales

VSIM ... WITHSCORES returns a score s from 0 to 1, where 1 is identical and 0 is opposite. The module README documents this; a test with three unquantized vectors (identical, orthogonal, opposite) returned 1, 0.5 and 0.4 FT.SEARCH and RedisVL (see the products table) return a distance instead: for cosine, 0 is identical and 2 opposite. Convert thresholds between APIs (cosine index only):

  • Score from cosine similarity: s = (1 + cosine) / 2.
  • Cosine similarity from score: 2s − 1.
  • Cosine distance from score: 2(1 − s).

Good for and not for

Good for

  • Session state and scratch memory that should expire on its own.
  • The last N messages of a conversation, read on every turn.
  • Shared locks, counters and queues across agent workers.
  • A cache of model answers keyed by meaning.
  • A hot slice of recent facts, refilled from a database.

Not for

  • The only copy of facts that matter. Keep the system of record in Chapter 08's database.
  • A vector corpus larger than RAM. Use a disk-based store (Chapter 11); keep the hot slice here.
  • Multi-record transactions or relational queries (use PostgreSQL).
  • A team that has not approved the AGPL, RSAL or SSPL terms. Use Valkey or review the license.

Use cases

1Support chat: session summary and last messages

Situation
A few thousand open support chats need summaries, ticket ids and the last twenty messages after worker restarts; abandoned chats should expire.
Why it fits
Refresh each chat’s hash and stream with EXPIRE 1800 every turn. XADD appends one message per entry. MAXLEN ~ trims approximately; the stream can exceed the cap. COUNT bounds the read. XREVRANGE history:alice + - COUNT 20 reads the newest twenty, newest first; the app reverses them (step 3).21
Pair with
PostgreSQL (Chapter 08) commits turn and numbered outbox row together. The relay’s Redis script atomically checks sequence, XADDs messages, updates summary/sequence and refreshes both TTLs. Old numbers return “already applied”; missing sessions or gaps trigger a PostgreSQL rebuild. Untested design sketch. Image defaults lose open chats in a crash (restart test below), so also enable the AOF.

2A fleet of workers sharing one job

Situation
Twelve workers watch one task list. Uncoordinated workers can summarize the same user, write conflicting notes and both pay for model calls.
Why it fits
Consumer groups assign each task to one worker. Commit under a unique job id before XACK; XAUTOCLAIM only after the slowest job’s timeout. For different tasks touching one user, SET key value NX PX 30000 grants one lease (a lock with a TTL). Leases reduce overlap; reclaims can repeat model calls. Database uniqueness prevents duplicate commits. The walkthrough tests XREADGROUP, XAUTOCLAIM and XACK. The lock guide accepts single-instance locks where occasional races are acceptable.22
Pair with
Database cases: accept any result with a unique job id; accept only the current owner with fencing (atomically check its database-issued, increasing generation). Calls can outlast leases; failover can lose them or roll back Redis INCR. Token checks on delete only protect another worker’s lease.

3Answer cache for repeated questions

Situation
An internal help bot pays for model calls for paraphrases of one question.
Why it fits
RedisVL's SemanticCache stores answers keyed by the question's embedding and returns one only when a new question is close enough. distance_threshold defaults to 0.1 (lower is stricter).23 Define a tenant tag in filterable_fields, store it on each entry and require its exact match on lookup. Skip shared caching for personalized answers. Key prefixes are not a security boundary: use ACL users and TLS (Chapter 17).
Pair with
Chapter 10, on setting and testing the threshold, exact-key caching and invalidation.

Scope and scale

JobThe slice read every turn (session summary, last messages, cached answers, leases): a bounded prompt and fewer repeat model calls.

  8. Measure vector RAM and query time

    The script creates a private network and fresh containers with the measurement limits, without published ports or FLUSHALL. It loads 10,000 seeded uniform-random (synthetic) vectors, reads used_memory and times 200 queries per method. FT.SEARCH returns only distances; both phases use identical vectors and queries.

    pythonmem_measure.pyTested
    import contextlib
import random
import struct
import subprocess
import time
import redis

N, DIM, Q = 10000, 1536, 200
rng = random.Random(7)
network = "memlab-09-measure"


def docker(*args):
    return subprocess.check_output(["docker", *args], text=True).strip()


@contextlib.contextmanager
def server(phase):
    name = f"memlab-09-{phase}"
    docker("run", "-d", "--name", name, "--network", network,
           "--cpus", "2", "--memory", "3g", "--tmpfs", "/data", "redis:8.10.3")
    try:
        address = docker("inspect", "-f",
                         "{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}", name)
        r = redis.Redis(host=address)
        for attempt in range(100):
            try:
                r.ping()
                break
            except redis.ConnectionError:
                time.sleep(0.1)
        else:
            raise RuntimeError("server did not become ready")
        yield r
        r.close()
    finally:
        docker("rm", "-fv", name)


def vec():
    return [rng.random() for _ in range(DIM)]


def blob(v):
    return struct.pack(f"<{DIM}f", *v)


def used(r):
    return r.info("memory")["used_memory"]


def median_ms(fn, queries):
    times = []
    for q in queries:
        start = time.perf_counter()
        fn(q)
        times.append(time.perf_counter() - start)
    times.sort()
    return round(times[len(times) // 2] * 1000, 1)


docker("network", "create", "--internal", network)
try:
    with server("index") as r:
        base = used(r)
        for i in range(N):
            r.hset(f"memory:{i}", mapping={"user_id": "alice", "embedding": blob(vec())})
        after_hash = used(r)
        r.execute_command(
            "FT.CREATE", "memidx", "ON", "HASH", "PREFIX", 1, "memory:", "SCHEMA",
            "user_id", "TAG", "embedding", "VECTOR", "HNSW", 6,
            "TYPE", "FLOAT32", "DIM", DIM, "DISTANCE_METRIC", "COSINE")
        while r.execute_command("FT.INFO", "memidx")[b"indexing"] not in (0, b"0"):
            time.sleep(0.5)
        after_index = used(r)
        queries = [vec() for _ in range(Q)]
        index_ms = median_ms(lambda q: r.execute_command(
            "FT.SEARCH", "memidx", "(@user_id:{alice})=>[KNN 10 @embedding $q AS d]",
            "PARAMS", 2, "q", blob(q), "RETURN", 1, "d", "DIALECT", 2), queries)
    rng = random.Random(7)
    with server("set") as r:
        base2 = used(r)
        for i in range(N):
            r.execute_command("VADD", "memvectors", "VALUES", DIM, *vec(), f"fact:{i}")
        after_set = used(r)
        set_ms = median_ms(lambda q: r.execute_command(
            "VSIM", "memvectors", "VALUES", DIM, *q, "COUNT", 10), queries)
finally:
    docker("network", "rm", network)
print("hash B/vector", (after_hash - base) // N)

Gotchas

Gotcha: a restart can erase the memory

Image defaults (save 3600 1 300 100 60 10000, appendonly no) lost a seconds-old key after restart: no snapshot had run. With appendfsync everysec the docs report about one second of loss, more with appendfsync no.1 AOF retained its write; process kill leaves the fsync window untested. No host crash was run.

Gotcha: a full server errors or evicts

On 64-bit systems maxmemory defaults to unlimited; set a dataset limit below container/host RAM. At the maxmemory threshold, the default noeviction rejects writes that need more memory and allkeys-lru evicts approximately least-recently-used keys; process RAM can exceed the limit. Run answer caches on an evicting instance and keep sessions, leases and vector-bearing hashes on a non-evicting one: the policy is server-wide, and an evicted hash silently drops out of search results. A test on both servers (limit 2 MB above idle) got write errors under the default and, under LRU, accepted all 4,000 writes and evicted earlier keys.24

Gotcha: release only your own lease

Acquire each lease with a fresh random token; release only your own. Use DELEX key IFEQ value (Redis 8.4 or later), which deletes only on a value match. The walkthrough rejected the wrong token and removed the matching lease with Redis's command, Valkey's DELIFEQ and the compare-and-delete Lua fallback on both servers.22

Unverified: open questions

  • Single-instance tests omit failover, clustered leases/rate limits and database commits.
  • SemanticCache runtime behavior, precision and filtered Vector Set recall at scale remain untested.

Verdict

Verdict: the hot tier, not the record

Pick it for sessions, recent history, answer caches and worker coordination backed by a database.

Default to Query Engine for per-user memory; consider Vector Sets or narrower types at RAM limits. Vector Sets remain beta; test filtered top-10 overlap against brute force before scaling. For BSD choose Valkey’s search bundle (no Vector Sets); its tag-filtered search returned expected matches.8 Keep vectors plus other keys below maxmemory with measured fork/fragmentation headroom. During snapshot/rewrite load, inspect used_memory_peak (INFO memory), rdb_last_cow_size and aof_last_cow_size (INFO persistence). At budget, move vectors to PostgreSQL (Chapter 08) or disk (Chapter 11). Chapter 23 uses regional Redis for sessions/caches, never signed facts.
